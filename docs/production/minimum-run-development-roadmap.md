# 廃TSUTAYA最小Runの開発ロードマップ

**Status: Draft（開発の叩き台。工程の実施・検証は未完了）**
**更新日: 2026-10-08**

## 目的と完了像

PvEアクションを土台に、探索・戦闘・アノマリー干渉・持ち帰り・都市でのビルド更新を一巡させる。同時にモデル、リグ、アニメーション、UI、Studio検証まで制作工程をプロトとして通す。

博士Questを受注し、廃TSUTAYAで任意にVHSを再生してモブと戦い、Mad Stomperをcureで沈静化する。花の胞子を持ち帰り、研究室でmad stompを修得・装備し、次のRunの戦闘で使うところまでを目標とする。

最初はHappierから手動の指示で進める。実際に発生した判断、差し戻し、再検証、待機を記録した後にLangGraph・Clefで半自動化する。自動化基盤の完成をゲーム試作の前提にしない。

## 最小範囲

- 対象マップは廃TSUTAYA。基本攻撃とランク1の纏絲勁、ヒール、cure、二段ジャンプを扱う。
- モンスターパニック映像VHSのCRT再生が、モブ出現イベントのトリガー。再生は任意。
- 汎用のモブ出現機能と、固有のVHS再生・内容判定を分ける。別の共通ギミックを初回から追加することは必須にしない。
- ラベルなし、誤表示、内容の差し替えの可能性を持つ。CRTに出た映像で内容を確認する。取得時・再生時の内部内容確定方法は仕様段階で決める。
- 再生実績は将来のポータル開放条件から参照できるようにする。今回Transition Portalは対象外。回数・同一媒体の再カウント・開始／完了の計数条件は未定。
- 成長は花の胞子とmad stompに限定。汎用スキルレアルートによる解放・強化は対象外。
- 操作、スキル状態、干渉Feedback、回収、リザルト、交換・融合、ビルド編集のUIをプロトで用意する。
- 全身モーフ、複数マップ遷移、全ランク実装は今回対象外。既存2マップ抽選を正式にTSUTAYA限定へ変更するか、検証経路だけ固定するかは仕様段階の判断。

## 共通化の方針

モブとMad Stomperは、行動開始・中断・終了、予兆とアニメーション、作用タイミング、対象・範囲・多重Hit判定、対象喪失・Run終了の後始末を共有できる範囲から設計する。

モブの撃破とGIANTの沈静化・胞子出現は個別結果として保持する。GIANTをHPで倒す通常敵に変更しない。既存の大型NPC領域センサー案は候補であり、採用は工程0で判断する。

## 手動開発から半自動フローへ

最初の作業単位は、仕様確認→作業指示→制作／実装→静的確認→Studio反映→実ゲーム検証→人間レビュー→課題と次指示の更新。各回に対象、元コミット、成果物、実施した検証、未確認、判断理由、次の担当を記録する。

半自動化の役割分担案:

- Happier：人間の指示・状況確認・実行への入口。特定モデル／バックエンドの採用は別途選ぶ。
- LangGraph：工程の状態保存、待機、再開、再検証ルートを管理。
- Clef：作業結果・チェック証拠を入力に、実装修正／アセット修正／再検証／人間判断への簡易分岐を補助。
- 定期起動：進捗集計、未完・未確認・停滞の抽出、ワークボード更新案。初回は開発タスクを無条件に起動しない。

まず人間とClefの判断を比較する。決定的なテスト失敗をClefでPassへ覆さない。仕様採用や世界観判断は人間へ返す。再試行回数、停止条件、モデルの提供経路・費用、起動時刻、重複起動防止とStudio作業の排他はフロー試作時に決める。

既存の単一実行方針を基準にし、並列化の必要が確認されるまでは実行主体を増やさない。半自動化はこのロードマップによる実行許可ではなく、手動記録から別途設計する工程。
