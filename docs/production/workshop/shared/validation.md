# 共通検証基準

**Status: Draft（個別用途の数値基準は未確定）**

各検証は `Pass / Fail / Unconfirmed / N/A`、条件、証拠、検証者、日付を記録する。N/Aには対象外の理由を添える。実施していない検証をPassにしない。

| 段階 | 確認すること |
| --- | --- |
| 入力・出力の成立 | 出典、版、保存、形式、寸法・単位、依存ファイル、要求と観測設定の一致 |
| 編集環境 | Blenderで法線・UV・Scale・材質、Rig・Weight、Target単体Bake等。UIはブラウザの配置・操作・状態 |
| 対象環境 | 通常Import、保存・再読込、実際のRig・Animator、接地・衝突・負荷・入力。Studio検証をHTML／Blender成功で代用しない |
| 人間レビュー | 意味、識別性、美術、仕様適合、採用範囲。対象版を指定する |

W01は縮小・背景違い・不要な参照要素の混入を確認。W02は意匠・裏面・厚み・UV・修正工数・用途上の価値を比較。W03／W04は単体と配置数・距離を含む条件を分ける。W05はR15と独自Rigを別々に確認。W06は仮データの操作とRobloxの実状態を分ける。

本番の三角形数・解像度・骨格数・配置密度・対象端末の予算は未確定。外部プラットフォームの上限を推奨制作予算として使わない。既存 [Roblox導入](../../roblox-import.md) と [Studioチェックリスト](../../studio-verification-checklist.md) を参照する。

失敗時は観測事実と原因推測を分ける。再発障害は [トラブルシューティング](../../troubleshooting.md) へ反映する。総時間、生成・処理時間、人間修正時間、人間待ち、差し戻し理由、次工程での再修正を記録し、自動化候補を実績から選ぶ。
