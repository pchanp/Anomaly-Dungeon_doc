# ゲームループとポータル遷移

**Status: Draft（草案）**

この資料は、現在整理されているAnomaly Dungeonのラン、経済、Player Anomaly、ポータル遷移の設計案を記録する。実装済み仕様ではない。世界設定上の事実はここでは確定しない。

## 現時点で合意している方向性

### 都市入口からランへの接続

ランの外側には、探索者が生活する都市入口を置く案とする。2Dワールドマップで施設を選び、小規模な施設内3Dで依頼、取引、ビルド管理、出発準備を行ってからダンジョンへ入る。この層は既存のRun中のポータル遷移を置き換えるものではない。

```text
2D WORLD MAP
    -> 施設内3D
    -> NPC / SHOP / QUEST / 出発準備
    -> ANOMALY DUNGEON
    -> 探索・戦闘・回収・遭遇
    -> 帰還
    -> 換金・クエスト報告・成長
    -> 2D WORLD MAP
```

ロビー、クエスト、換金・成長の詳細は、それぞれ[ロビー／ワールドマップ](lobby-world-map.md)、[クエスト](quests.md)、[経済と成長](economy-and-progression.md)に分離する。現時点の実装済みロビーや単一目標のQuest Attributeを、この草案の実装済み仕様とは扱わない。

### 基本ゲームループ

1回のランは、原則として以下の循環で構成する。

```text
依頼を受ける
    -> ダンジョンを探索する
    -> 帰還する
    -> 報酬を受け取る
    -> 換金・強化する
    -> 次の依頼を受ける
```

- **クエスト**はラン中の目的である。達成条件、持ち帰る対象、探索上の判断に関わる。
- **実績、FILE、発見**はクエストから分離する。探索中に見つかる情報と、長期的な収集・学習の要素として扱う。
- FILEは、後述するポータル遷移の傾向をプレイヤーが学ぶための経路になり得る。ただし、情報の見せ方と正確さは未決定である。

### 資産と死亡リスク

- 通常インベントリとは別に、重要資産を入れるための**Secure Slot**を設ける案とする。
- Secure Slotはおよそ4枠を想定し、ここに入れた重要資産は死亡時にも確実に持ち帰れるリスク管理の手段とする。
- 枠数、対象アイテム、死亡以外の喪失条件、入出庫のタイミングは未決定である。

### Player Anomaly

- Player Anomalyは、原則としてプレイヤーにとってデバフである。通常のプレイヤー状態の方が経済面・ゲーム進行面で有利な前提を維持する。
- アノマリー化したプレイヤーには、Secure Slotなど通常資産の価値または利用に制約が生じる案とする。具体的な制約と、資産を持ち帰る方法は未決定である。
- 代償的な利点として、固有アクションや独自スキルを持たせる。また、通常は高価値アイテムまたは金銭を必要とするビルドスキルの獲得・強化を、アノマリー化中に1回だけ無条件で行える案とする。
- ビルドスキルは、ダンジョンで得たアノマリーの痕跡に曝露された物質を用いる案とする。アノマリー化したプレイヤーは、自身へ直接刻み込むことで即時に1回分の獲得または強化が可能になる。
- Player Anomalyは1ランにつき最大1人を基本案とする。全員がアノマリー化して通常の協力・経済・リスク管理の前提が失われ、別ゲームモード化することを避ける。
- Player Anomalyへのキル報酬は大きくしない。直接PvPをランの主目的にしない。
- アノマリー化はラン単位の状態として扱い、次のランでは通常プレイヤーへ戻る方向を基本案とする。

Player Anomalyと、ダンジョン内に存在するAnomaly Entityは別の概念として扱う。個別能力やアノマリーそのものの記録は[`../anomalies/`](../anomalies/)に置く。

## ダンジョンとポータル

### 深度ではなく遷移としての探索

ダンジョンは、固定的な階層や一方向の深度を必ずしも持たない。プレイヤーはバックルーム的な複数のマップをポータルで遷移する。

- ポータルは「次の階」ではなく、次の空間への遷移として扱う。
- 「深さ」は単一のベクトルを指す必要がない。ワンフロアの終点のような最深部的空間へ突然出ることも、田舎の夏休みのような空間へ出ることもある。
- 最深部的な空間は、絶対的な最終階層ではなく、出現し得る特殊空間の一つとして扱う案とする。

### 個人状態による確率の変化

ポータル遷移先は完全なランダム抽選ではない。少なくとも以下の内部状態によって、候補空間の出現確率が変化する案とする。

- Exposure
- Individual Anomaly
- 現在地または直前の空間
- クエスト状態
- 所持アイテム

Exposureは単純な深度や進行度ではなく、ポータルの遷移確率を歪める内部パラメータとして扱う。高Exposureが特定の方向への進行を保証するものにはしない。

プレイヤーには計算式や各候補の正確な確率を直接表示しない。FILEなどを通じて「この状態ではこの種類の空間に出やすい」ことを経験と知識から学べる設計を目指す。目標は、**知識により確率を予測できるが、結果を完全には制御できない**状態である。

### マルチプレイ時のParty State

マルチプレイでは、ポータル開放または通過判定時にパーティ全員の状態を用いて遷移先を決める。単純なExposure総和だけで決めず、以下を含む**Party State**を入力とする案を検討する。

- Exposureの平均、最大値、分布
- Player Anomalyの有無
- Individual Anomalyの種類
- 特定アイテムの所持状況
- クエスト進行状態
- 現在地または直前のマップ

遷移処理は、以下を基本案とする。

```text
特殊条件を評価する
    -> 条件を満たす場合は確定遷移
    -> それ以外はParty Stateから候補に重み付け
    -> 重み付き抽選で遷移先を選ぶ
```

これにより、「全員が特定のアイテムを持つ」など学習可能な条件は確定遷移にできる一方、Exposureや分布などの状態は確率に影響するだけに留められる。

## 未決事項

- アノマリー化したプレイヤーの具体的な帰還方法と、Secure Slot・通常資産への最終的な制約。
- 報酬額、キル報酬、換金・強化コストの具体値。
- Exposure、Party State、候補重みの計算式と閾値。
- ポータルを開く／通過する判定の正確なタイミングと、パーティから遅れたプレイヤーの扱い。
- 確定遷移の条件一覧、候補マップ群、FILEの取得・表示・信頼性の仕様。
- 1ランの開始・死亡・帰還・アノマリー化解除の詳細な状態遷移。
