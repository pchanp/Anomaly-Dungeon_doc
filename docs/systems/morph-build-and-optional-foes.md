# 全身モーフ、ビルドと任意挑戦の強敵

**Status: Idea（アイデア・未採用）**  
**記録日: 2026-10-06**

都市で全身の姿とスキルを組み、その違いをダンジョンの戦闘で実感する構想。利用履歴が残り、未知の存在への接続条件にもなる。今回の相談を記録したもので、実装・採用・現行Runの範囲変更は行わない。

## 1. 全身セットとしてのモーフ

モーフは全身セットを選ぶ方式。外見に加え、通常攻撃のモーション、身体の特性、NPCの反応を変える案とする。アノマリー用に制作した人型も、隠しセットとして利用できる可能性がある。

- 共通人型リグを土台に、関節構成、基準姿勢、装備位置を揃える。
- モーフIDから、モデル・動作・性能・装備制限・NPCの反応を参照する。表示名や見た目から判定しない。
- NPCの反応は、その人物の目的や関係に沿って変える。世界の真相を解説する役にはしない。
- アノマリーに似た姿になっても、Player Anomalyへの変化やAnomaly Entityとの同一性を意味しない。

共通リグなら実装負担を抑えられるが、モデルの変形、接地、装備、攻撃判定を確認する必要がある。R15移動アニメーションの実装記録はあるが、実際のプレイヤーリグとの互換性は今回未確認。

## 2. 性能とスキル制限を組み合わせる

例として、通常攻撃が強力なモーフは攻撃系スキルを装備不可とし、移動・回避・探索・補助で支えるビルドを作る。強みだけでなく攻撃後の隙などを持たせ、単純な上位互換にしない。

4装備枠を維持し、モーフごとに装備可能なスキルを変えるのは検討案。系統全体を禁止するか、個別スキルに制限を付けるかは未決定。通常攻撃の威力、範囲、間隔、連携まで変える場合は、外見変更より調整負担が増える。

既存のワンツー、フルアタック4連撃、武器動作、通常攻撃を変えるCOBRAとの優先順位は未決定。モーフで既存の通常攻撃規則を黙って置き換えない。

## 3. 研究室でモーフとスキルを一緒に組む

ブティックでモーフ、別施設でスキルを変更する導線では、ビルド完成までの往復が増える。都市ロビーの博士の研究室で、両方をまとめて編集する方向を検討する。ダンジョン内の研究所とは別の場所である。

編集画面ではモーフの特徴と使えないスキルを確認し、その場で装備を調整する。試着中は仮の構成を保持し、確定時にまとめて適用する案。都市で変更しRun中は固定する案、構成のセット保存も将来候補とする。

ブティックは当初の候補であり、設置を必須としない。衣装入手や細部調整の施設として残すかも未決定。

## 4. 便利だが原理が分からない

アノマリー化、スキル、モーフは、有効利用できるためプレイヤーが使う。その仕組みや相互関係は説明し尽くさない。

研究室に機能があることだけで、博士が発明した、技術的に関与している、身体を作っているとは確定しない。似た表示や応答によって共通原理を疑わせても、同じ原理の証拠にはしない。

既存の博士Quest・研究解放・専用スキル交換というゲーム上の条件は維持する。博士の関与を曖昧にすることは、それらの操作条件を隠すことを意味しない。

## 5. なぜか消えない利用履歴

モーフ回数やスキル強化回数が累積される。元の姿へ戻しても履歴は戻らず、何に使われる記録か分からない。「カルマ」は着想上の呼び方であり、正式名称や道徳的な評価とはしない。

当初は実際のゲーム影響がほぼない記録を想定した。その後、隠しアノマリー・遭遇の解放条件にも利用する案へ広がった。能力への罰を付けることは今回決めていない。

| 記録 | 数える条件の検討案 |
| --- | --- |
| モーフ変更回数 | 別のモーフへの変更を確定したとき。試着、同じセットの再選択、スキル編集だけでは増やさない |
| スキル強化回数 | 実際にスキルレベルを上げたとき。装備の組み替えとは別に扱う |
| ビルド変更回数 | 会話で挙がった関連案。強化と編集のどちらを指すか、独立して保存するかは未決定 |

画面に小さく「変更履歴：17」と表示する、装置やNPCの短い応答が変わる、といった演出は候補。永続履歴の保存、リセット、失敗・再送時の重複加算防止は実装時の課題。

回数は熟練度の間接的な手掛かりにはなるが、技能を直接測る値ではない。頻繁に試す初心者と、同じ構成を使い続ける熟練者を区別できないため、単独で難易度を決める指標にはしない。

## 6. ビルドを試せる、マップごとの強敵

マップのコンセプトに反しない範囲で、数種類の強敵候補からランダムに遭遇する構成を検討する。ソウルライクな手応えは、HPや火力だけでなく予兆、間合い、反撃の隙、欲張る判断に持たせる。

- その場所で守る・運ぶ・探すなどの行動を持つ強敵。
- 場違いな姿だが、その場所の音・物・現象に反応する存在。
- 同じ相手に対し、モーフとスキルによって得意な攻略が変わる。
- 基本操作で対処でき、特定セットの所持だけを突破条件にしない方向を検討する。

出現数、抽選、配置、報酬、必須討伐にするか、迂回できるかは未決定。通常敵、戦闘可能なAnomaly Entity、倒す対象ではないAnomaly Entityを分け、通常敵の出現枠とアノマリーの出現枠を混同しない。

「戦場」は敵モブなし・アノマリー同時発生数0という既存Ideaがあるため、全マップへ一律に強敵を追加しない。

### 8/32：夏の向こう側を連想させる敵

8/32は何が現れてもおかしくない感覚を持つ一方、夏の向こう側を連想させる象徴的な強敵も置ける。正体や季節の意味を確定せず、戦う前から何かをしている存在として探索へつなげる。

以下は相談中に挙がった例示であり、個別の採用候補として確定していない。

| 着想 | 行動・戦闘のイメージ |
| --- | --- |
| 夏の抜け殻 | 攻撃後に殻が残り、本体の移動先を読む |
| 帰らなかった誰か | 夏服の人影。背を向けた状態と振り返った後で間合いが変わる |
| 終わらない夕立 | 雨音の変化が攻撃の予兆になる |
| 夏を片付けるもの | 季節の残り物を集め、回収と攻撃を見分けて介入する |

8/32は同一マップの状態変化という既存方針を維持する。帰還制御、Exposure、Run Lifetimeとの両立は別途検討する。

## 7. 自分のタイミングで挑める未知の存在

序盤から持っているアイテム等を使い、任意のタイミングで強敵に挑む案。利用履歴に応じて、以前から持っていたものに新しい操作が現れる構成も考えられる。

着想例はFF8のディアボロス。魔法のランプで任意のタイミングに挑め、相手のレベルがパーティの平均レベルに連動する仕組みを参照した。名前、姿、演出は流用しない。[確認に用いた攻略資料（二次資料）](https://www.gamerguides.com/final-fantasy-viii/guide/walkthrough/disc-1/the-magical-lamp)

検討中の役割分担は、履歴で遭遇を解放し、現在の構成や過去の突破状況から挑戦段階を考えること。回数に比例して際限なく敵を強くし、試行錯誤を不利にする設計は避けたい。強さを挑戦開始時に固定する案もある。

上の段階では数値だけでなく攻撃の組み合わせや隙の作り方を変える。利用履歴を存在が何かの資格として扱うことで、記録の意味を疑わせる。博士が設定した条件か、その存在が反応しているだけかは断定しない。

具体的なアイテム、閾値、挑戦場所、ソロ／Party、再挑戦、消費、敗北時の扱い、報酬は未決定。既存の専用スキル交換条件やAnomaly Entity出現規則に対する追加・例外は、採用時に判断する。

## 採用前に決めること

- モーフ性能と装備制限、武器・構え・フルアタックとの優先順位。
- モーフ変更とPlayer Anomalyの独立性、両方が有効な場合の扱い。
- 編集可能な場所、Run開始時の固定範囲、永続保存する構成と履歴。
- 履歴で解放する対象と、操作上明示する条件・曖昧に残す意味の境界。
- 強敵の分類、マップごとの候補、交戦の任意性、出現枠、Partyの難易度基準。

既存仕様の変更は未採用。永続的な蓄積だけで優位性が決まらない方針を維持し、構成、操作、観察、判断を主な遊びにする。
