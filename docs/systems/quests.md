# クエスト

**Status: Draft（草案）**

この文書は、ランの目的としての Quest の情報設計と世界内での扱いを定義する。Quest と FILE、Achievement、Discovery の分離は既存の[ゲームループとポータル遷移](game-loop.md)に従い、現在の実装範囲は[現在の実装状況](current-implementation.md)を参照する。

## 基本思想

クエストの目的は明確にする。「世界の謎を解け」ではなく、生活的で具体的な依頼を基本にする。例として、治療に必要な薬草や医薬品材料の回収、旧施設からの部品回収、行方不明者の所持品探索、指定物品の持ち帰り、指定地点の調査、写真撮影、特定の異常現象の確認がある。

基本構造は以下とする。

| 要素 | 方針 |
| --- | --- |
| 目的 | 明確 |
| 手段 | 危険 |
| 対象 | 異常であり得る |
| 依頼主の事情 | 部分的に理解可能 |
| アノマリーの意味 | 不明 |

Questは、ダンジョン入口ロビーからのマップ抽選に関与しない。目的地を制御する条件ではなく、抽選されたマップ内でプレイヤーが達成を目指す目的として扱う。最小Run終了時には、獲得物と保有Questごとの達成状況をリザルト画面に表示する方針である。詳細は[005: 都市ロビーから開始する最小Runの範囲](../decisions/005-minimum-lobby-run-scope.md)を参照する。

## 依頼主と感情表現

依頼主は世界設定を説明するNPCではない。たとえば家族の治療を必要とする人物は「娘の治療に必要なんです」まで伝え得るが、なぜその薬草が必要か、なぜダンジョンにしかないのか、安全かどうかまで説明する必要はない。

依頼主は必要事項を話し、受け取り後に短く礼と報酬を示す演出を基本候補とする。深い事情を語らないことによって、プレイヤーが背景を補完できる余地を残す。

## 対象物の不明さ

目的物は用途不明、異常な形状、生物的、明らかに危険、普通の物品に見えるが挙動がおかしい、といった性質を持ち得る。重要なのは、依頼の目的が分かる一方で、依頼物の意味や世界的な位置付けが分からないギャップである。

目的の不明瞭さを常態化させない。謎にするのは「それが何か」「なぜ必要か」「何が起きているか」であり、プレイヤーが何をすべきかではない。
