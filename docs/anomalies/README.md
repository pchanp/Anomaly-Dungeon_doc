# Anomaly documentation

Use one Markdown file per anomaly when practical. File names should be stable and readable, such as `miw.md` or `dev-null.md`.

Documents may include a System ID, Game Name, concept, type, behavior, affinity, visibility, components, trigger, runtime behavior, player interaction, Anomaly Exposure relationship, related Player Anomaly, prototype status, uncertainties, implementation notes, and related documents. Include only fields that help describe the specific anomaly.

System IDs and game names are separate concepts. A game name is optional; do not invent one only to satisfy a template. Preserve established names and capitalization.
