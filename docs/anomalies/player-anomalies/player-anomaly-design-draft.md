# Player Anomaly

**Status: Design Draft（設計草案・未確定）**

**Type: Gameplay / Worldbuilding / Cognitive Anomaly**

**System ID: `player_anomaly`（仮）**

**関連概念: PvPvE、PvEvE、Anomaly Exposure、Individual Anomaly**

## この草案の位置づけ

この文書はPlayer Anomaly全体の設計概念を再検討する草案であり、個別のAnomaly Entityの資料ではない。`player_anomaly`は仮のシステムIDであり、ゲーム内表示名や実装上のIDとして確定しない。本文の世界観上の位置づけも設計草案であり、確定した世界設定やプレイヤーへ開示する情報として扱わない。

既存仕様の変更を含むが、現時点ですぐに実装へ反映するものではない。既存の[ゲームループ](../../systems/game-loop.md)、[ゲームルール](../../systems/game-rules.md)、[判断001](../../decisions/001-game-loop-and-portal-transitions.md)、[採用済みの判断019](../../decisions/019-player-anomaly-runtime-pvp-and-return.md)を、この草案によって採用済みの新仕様へ置き換えたとは扱わない。

既存資料との主な差分・要整理事項は以下のとおり。

- 既存の「原則デバフ」という位置づけに対し、この草案では、世界を理解するための前提や関係性の変化を中心に置く。経済面・ゲーム進行面の有利不利は、この草案では確定しない。
- 既存のExposure閾値・待機キューによる発生設計に対し、発生条件・タイミング・頻度とExposureとの関係を未確定として再検討する。同時発生上限や待機キューの新しい扱いは決定しない。
- 既存のRun単位の状態と次Runでの通常状態への復帰に対し、一時的／継続的な変化、解除・回復・不可逆性を未決定事項とする。
- PvEvEへの構造転換は体験上の狙いであり、既存のHP 80%下限、相互キル、固有Runtime、専用スキル、固有Portal、報酬の具体ルールをこの草案で変更・確定しない。

[Visible / Invisible Inversion](visible-invisible-inversion.md)は既存の個別案として参照する。そこにあるExposureによる発生やRun終了後の復帰を、Player Anomaly全体の必須仕様としてこの草案へ引き継がない。現行プロトタイプの状況は[現在の実装状況](../../systems/current-implementation.md)を参照する。

## 1. 概要

Player Anomalyは、プレイヤー自身が異常化する可能性を扱う設計概念である。

当初のゲーム体験上の目的は、PvPvEからPvEvEへの構造転換を通じて、プレイヤーが当然視していた敵・味方・未知の存在の区別を崩すことにある。

プレイヤーは探索する仲間、敵対するプレイヤー、敵性存在、未知の現象を観察しながら行動する。しかし、異常化によってその分類や関係性そのものが揺らぎ、プレイヤー自身も世界の異常現象を構成する一部となり得る。

異常化するという設定自体は維持する。一方で、発生条件、タイミング、頻度、ゲームシステム上の実装方法は未確定とする。

## 2. 設計意図

### 2.1. 観察者としての立場を崩す

プレイヤーは通常、ゲーム世界を外側から観察し、状況を理解し、攻略する立場にある。

Player Anomalyは、この立場が保証されていないことを体験させるための仕掛けである。

- 異常を観察する側が、異常な存在として扱われることがある。
- 自分にとって合理的な行動が、他者からは理解不能なものに見えることがある。
- それまで共有されていた敵味方の認識や、協力するための前提が崩れることがある。
- 世界を理解するための分類やルール自体が、状況によって成立しなくなることがある。

単にプレイヤーへデバフを与えることではなく、プレイヤーが世界を理解するために用いていた前提を変化させることを目的とする。

### 2.2. PvPvEからPvEvEへの構造転換

通常のPvPvEでは、プレイヤー同士の対立や協力がゲーム体験の重要な構造となる。

Player Anomalyは、この構造を崩す演出として機能し得る。

重要なのは、敵の種類が変わることだけではない。誰が敵で、誰が味方なのか、何を危険と判断するのか、どの情報を信頼できるのかといった、プレイヤー間で共有されていた前提そのものが揺らぐことである。

PvEvEへの転換は、必ずしも対人戦の完全な消滅を意味しない。対立が継続していても、敵味方を判断する基準や他者への認識が変われば、ゲーム体験としての構造転換は成立し得る。

### 2.3. 特別な結末ではなく、起こり得ること

異常化は、特別な存在だけに起こる現象や、ゲームオーバーのような決定的な結末に限定しない。

程度や形態には差があっても、プレイヤー自身が異常な存在となる可能性は、ゲーム世界の中に常に存在する。

これは、プレイヤーが必ず異常化するという意味ではない。異常化が世界の外側から与えられた特別な罰や、選ばれた者だけの宿命ではないことを示すための設計方針である。

## 3. 世界観上の位置づけ

### 3.1. 異常化と自己の連続性

異常化は、単純に人間性を失ったり、敵キャラクターへ変身したりすることだけを意味しない。

ある対象への執着、身体的な切実さ、繰り返される習慣、認識の偏りなどが、その存在と世界との関係を変えてしまうことも含む。

外側からは奇妙な行動に見えても、本人にとっては切実で自然な行動である場合がある。

その行動を理解できたとしても、対象の奇妙さや恐怖が消えるとは限らない。理解と恐怖、嫌悪と親近感、警戒と愛着が同時に成立する余地を残す。

### 3.2. Anomalyとの連続性

既存のAnomalyは、単なる敵や攻略対象ではない。それぞれ固有の挙動や事情を持ち、プレイヤーに恐怖、好奇心、共感、愛着などを生じさせ得る存在である。

Player Anomalyも、この連続性の上に位置づける。

プレイヤーが既存のAnomalyに対して感じた理解や違和感が、別の状況で自分自身に向けられる可能性がある。

プレイヤーはAnomalyを理解しようとする一方で、自分自身も他者から理解されない存在になり得る。

### 3.3. 妄人（ワンニン）を参照した設計上の視点

『クーロンズ・ゲート』の妄人を、執着と存在の変容が結びついた表現の参照元とする。

妄人化を特別な結末として扱うのではなく、何かに取り憑かれることや、特定の対象との関係が変質することは、程度の差こそあれ誰にでも起こり得るものとして捉える。

ただし、妄人とPlayer Anomalyを同一の存在分類や変身システムとして扱うことを意味しない。参照するのは、理解可能な感覚や執着が、理解しがたい存在のあり方へとつながる構造である。

## 4. ゲームプレイ上の表現方針

Player Anomalyは、必ずしも専用のステータスや明示的なイベントによって表現する必要はない。

以下は表現候補であり、実装を確定するものではない。

- 認識の不一致: プレイヤーが見たものと、資料や他のプレイヤーが認識しているものが食い違う。
- 行動の意味の変化: プレイヤーにとって自然な行動が、他者からは異常な行動として扱われる。
- 関係性の変化: それまで仲間や敵として認識していた存在との関係が、異常現象を契機に変化する。
- 観察と関与の反転: 異常を観察するための行動が、いつの間にか異常現象の一部となっている。
- 事後的な理解: 発生時点では原因がわからなくても、資料や過去の経験を振り返ることで、プレイヤー自身が現象とのつながりを見いだせる。

異常化の原因や条件を完全に説明する必要はない。ただし、不透明であることを理由に、プレイヤーが経験を振り返るための手掛かりまで排除しない。

## 5. Anomaly Exposureとの関係

Anomaly Exposureは、異常への接触や曝露に伴うゲーム上のリスクを管理するための尺度として検討する。

一方、曝露量と異常化を同一のものとして扱うかは未確定とする。

異常への接触量が増えることと、特定の対象への執着が生じること、認識が変化すること、プレイヤーが異常な存在として扱われることは、必ずしも同一の過程ではない。

そのため、すべての異常体験を単一の数値や閾値によって説明することは必須としない。

Anomaly Exposureを採用する場合も、異常との関係性や認識の変化をすべて数値へ還元しない設計を検討する。

## 6. 設計原則

1. プレイヤーは異常を観察する立場にあるが、その立場は保証されていない。
2. 異常化は、単なる不利益や状態異常ではなく、世界を理解するための前提を変化させ得る。
3. 異常化は特別な結末に限定されず、程度や形態の差を伴って起こり得る。
4. 既存Anomalyと同様、恐怖、共感、嫌悪、愛着が同時に成立する余地を残す。
5. 原因や挙動の一部は学習可能であっても、理解や分類によって現象との関係が完全に解消される必要はない。
6. ゲーム上の予測可能性が必要な危険と、理解しきれないまま経験する現象を区別する。
7. プレイヤーアノマリーという設定を、必ずしもゲーム内の用語や明示的な説明として提示する必要はない。

## 7. 未決定事項

以下は今後の設計・プロトタイプ検証の対象とする。

- 異常化の発生条件（曝露、行動、環境、イベントなど）
- 異常化が発生するタイミングと頻度
- 一時的な変化と継続的な変化の区別
- 他のプレイヤーから異常化がどのように認識されるか
- PvPvEからPvEvEへの転換を、どのようなゲームプレイ上の変化で表現するか
- Anomaly Exposureと異常化の関係
- 異常化の解除、回復、不可逆性の扱い
- ソロ・協力・対人要素の各状況における体験の整合性

これらは、異常化がプレイヤーにどのような経験をもたらすべきかを明確にしたうえで決定する。

## 8. 設計上の要約

Player Anomalyは、プレイヤーを単に異常なキャラクターへ変化させるためのシステムではない。

異常を観察し、分類し、攻略する立場にあったプレイヤー自身が、世界から理解されない存在になり得ることを体験させるための設計概念である。

PvPvEからPvEvEへの構造転換は、その狙いをゲームプレイとして強く表現する手段の一つである。

ただし、異常化そのものはその瞬間だけに限定されない。既存Anomalyとの遭遇、資料の読解、他者との認識の不一致など、さまざまな経験を通じて、プレイヤーが自分自身と異常との連続性に気づく余地を残す。

異常を観察する者もまた、異常な存在となり得る。その可能性は、特別な結末ではなく、この世界に常に存在している。
