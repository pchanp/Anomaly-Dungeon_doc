# stray

**Status: Idea（アイデア・未採用）**
**Type: Anomaly Entity**
**記録日: 2026-10-08**
**Prototype: 未実装。今回Studio確認・コード変更は行っていない。**

## 名前とコンセプト

- **System ID候補:** `stray`。小文字表記。実装IDへの登録は未実施。
- **ゲーム内表示名:** 未定。

帯電可能なオブジェクト間を、行き場なく渡り続ける光。彷徨う・逸れる印象と、rayの音を重ねた名称候補。落ち着けない移動と、循環から一手だけ外れる挙動を特徴とする。

キャラクターモデルを必須にせず、スクリプト上の状態、物体との接続、BeamとAttachmentによる光で存在を表現する。不可視の人型がいる設定ではない。Player Anomalyや通常モブと混同しない。

機器間を移動する既存作品のキャラクターが着想として挙がったが、姿・名称・固有設定を再現せず、物体間移動と空間の危険化を本案の特徴とする。

## 滞在と移動

プレイヤー付近の一定距離にある、帯電可能なオブジェクトを接続候補とする。始点と終点は各オブジェクトの頂点・上部に置く想定。正確な接続位置はマップ側の候補点として指定する案。

物体間を渡るのは、全長が一斉に攻撃するレーザーではなく、**短い光の区間が高速で走るパルス**。約2秒間隔の移動・発射を想定するが、速度、長さ、太さ、滞在時間、予兆時間は未定。

```text
始点A ●────────────────● 終点B
              ━→   短い光の区間
              ▒
              ▒    下方向の危険帯
──────────────▒──────── 地面
```

光の区間から下方向へ、地面に垂直な危険範囲を取る。区間の移動に合わせて縦の帯が空間を横切るため、簡単なジャンプだけでは避けにくい。通常移動による位置取りと移動スキルを活かす方向。

研究所などの機器配置と相性がよいが、出現マップを研究所へ固定しない。建物構造・新規レイアウトは提案しない。都市の博士の研究室とダンジョン内の研究所は別である。

## 経路選択と安全位置

基本は候補オブジェクトからのランダム選択。プレイヤーと交差しやすい経路を優先する選択も検討する。XZ平面でプレイヤー位置と候補線分の距離を測り、近い経路の重みを上げる方式が候補。必ず命中する線を作る意味ではない。

発射前に経路を予告し、その時点の位置で固定する案。発射後まで追尾して回避先を塞ぐ挙動は未採用。速度を使った予測位置の利用は将来候補。

プレイヤーは物体配置から、接続経路と交差しない安全位置を探せる。ただし、別経路同士が交差する位置は、直前に通過済みでも安全とは限らない。

直前と同じ経路を避ける規則も候補。逆向きの同じ物体間移動を同一経路と数えるか、候補が足りない場合の扱いは未定。安全を判断できる予兆を残し、移動スキル未所持で常に被弾する配置にはしない方向を検討する。

## 自身の循環に気づき、一手変える

strayが自身の経路履歴から循環を検出し、次の一手だけ別の経路へ変える案。プレイヤーが規則に気づいたことを検知する設定ではない。

```text
A → B → C → A → B → C
                 循環を検出
A → B → D → …    次の一手を変更
```

接続先IDの履歴を到着時に更新する。短い列が2回続いたら変更する程度から試す案。検出する列の長さ、履歴保持、変更先の選択、通常経路への復帰は未定。別候補がなければ通常移動を続ける案。変更する一手にも予兆を出す。

規則を読めば避けられるが、反復が永続的な安全を保証しない存在として扱う。

## 表示・当たり判定の実装候補

Beamには衝突判定がないため、見た目と判定は分離する。透明な箱や座標計算、空間クエリを利用する。Anomaly Entityの状態を保持するために、表示用キャラクターモデルは必要としない。

- Serverが始点・終点・開始時刻・速度・区間長と命中を確定する。
- Clientは同じ情報から光を滑らかに表示し、毎フレーム位置を通信しない案。
- 当たり判定は現在位置だけでなく、前回から今回までの危険帯の通過範囲を扱う。高速移動中の取りこぼしと、プレイヤー側の移動も検討する。
- 一発につき同じプレイヤーへ一度だけ命中する案。複数対象への貫通可否は未定。
- 共通の更新ループ、発射中だけの判定、表示用オブジェクト再利用を候補とする。毎秒20回程度の判定は試作値であり、採用済み・性能保証ではない。

Blockcastは最初の衝突を返し、開始時から重なる物体を検出しないため、それだけで複数対象・初期重なりを解決したと扱わない。床の段差、上下階、壁で止まるか、頂点の高度差、縦の帯の幅と底面形状で判定方法が変わる。

上部の光だけを表示して下で被弾させないよう、地面までの放電・薄い揺らぎ・足元の反応を検討する。

## 効果と境界

| 項目 | 現時点の案 |
| --- | --- |
| Trigger | 選択経路の予告後にパルスが移動し、危険帯と接触する |
| Condition | 対象の接触・交差。帯電候補の範囲、発射条件、対象資格は未定 |
| Effect | 接触ダメージは`Damage`。経路・循環・移動先はEntity自身の状態として保持 |
| 対象・作用範囲 | 命中したプレイヤー。Party全員への自動ダメージではない |
| 保存・終了 | ダメージは即時。Entityと履歴はRun内Runtime候補。マップ遷移時の保持・破棄は未定。Run終了で後始末 |
| 重ね掛け | 一発一対象一回という命中制限案。別パルスのDamageはイベントごとに解決 |
| Feedback | 次の接続先と経路の予兆、移動する光、縦の危険帯、到着反応。機器点灯や動作変化は演出候補 |

**requires_code: true（実装する場合）**。候補点管理、選択、履歴・循環判定、同期表示、通過判定、ダメージと後始末が必要。実装許可や最小Runへの追加を意味しない。
