ROLE-C-004 試聴の記録（廃TSUTAYA・探索系）

個人試聴は一定時間で自動終了し、開かなかった項目はその時間を越えると訪問できない。この候補は試聴中にプレイヤー自身が中断する操作を追加し、その瞬間に未閲覧の項目を1件だけ個人記録として残す。残るのは既存UIが持つ名前と選択結果だけで、映像や音声の実内容は作らない。試聴中は移動も通常攻撃も他のスキルも発動できない。

(b) 設計仮説とプレイヤーの選択

設計仮説: 試聴の自動終了を、視聴の期限ではなく、何を1件だけ持ち帰るかを決める判断の期限として使う。店内は袋小路で視界が分断されているため、鳴っている間に周囲を確認できないことを前提にして、その時間を情報 而不是防御に振り切る。

狙う体験

「聴いたつもり」で店内を出ることを、「1件だけ持ち帰る」判断に変える。記録は本人にしか見えないため、Partyとの会話が新しい情報になる。記録しただけでは中身は分からないので、実際に開いて初めて得られる、という二段構えが残る。

判断と代償

最後まで鳴るのに待つか、自分のタイミングで中断して1件記録するか。記録できるのは未閲覧1件だけ。記録すれば同じ試聴に残ったほかの未閲覧品には到達できない。試聴中は移動も攻撃も他のスキルも発動できず、無防備になる。

作用図 — 試聴の時間軸、個人の中断の瞬間と記録の消費

この図で分かること: 中断は既定の自動終了より前にのみ成立し、中断した瞬間にだけ記録が生成される。記録は1件・単回・本人限定である。試聴中は操作が受け付けられず、セッションが終われば解除される。共有BGMも他プレイヤーの画面も変化しない。

図では確定しないこと: 記録できる項目がどの項目に選ぶか、記録後に同じ棚を再検索できるか、記録した項目を再度開いたとき何を見せるか、試聴中にカメラとUI操作を残すか。図の左右は試聴機の設置位置でも部屋の並びでもない。

(c) Trigger・Condition・Effectの契約

三つのEffectを分ける。終了時刻の置換、操作の封じ、個人記録の保持は寿命も検証主体も異なる。

Effect 1 — RuleOverride（即時・操作）

Trigger対象がTSUTAYAの試聴機で個人試聴を開始し、そのセッションが継続中に、対象自身が中断操作を行うこと。棚の操作や外部イベントでは発動しない。
Condition個人試聴セッションが継続中であること。対象が操作者であること。1セッションにつき1回だけ有効。
Effect種別・結果RuleOverride。対象は個人の試聴セッションの終了時刻だけに限る。当該セッションを、PreviewDurationによる自動終了より前の時刻で終了させる。以降の再生は行わない。共有BGMの選択、配信、変更は行わない。
対象・作用範囲対象プレイヤーの個人試聴セッション1件。範囲は個人。試聴機の物理的な挙動にも店内の共有BGMにも影響しない。
保存境界・終了保存境界は一時、解決はinstant。終了時刻を確定した時点で適用解決は終わる。設定時刻の到達または切断でセッションは破棄。マップ離脱とRun終了でも破棄。
重ね掛け例外なし。同一Effectと同一対象は非加算1件。1セッションにつき1回だけ有効で、再適用しても新しい終了時刻を作らない。/dev/nullのSkillやItemの結果傍受、および試聴サービスの自動終了以外の打ち切りとの優先順位は定義せず保留する。
Server / ClientServerがセッションの存在、対象が操作者であること、1回の上限を検証する。クライアントは終了時刻を指定できない。停止演出は個人クライアントのみ。共有BGMの音量や再生状態、他プレイヤーの試聴表示は変更しない。
Feedback成功: 再生が止まる事象と時刻を出さない短い個人表示。失敗: 試聴中でない場合に同じ操作をしても共有BGMや他プレイヤーの状態には影響しない。不明: なぜそこで止めたのか、試聴内容のどの位置で止めたかは表示で確定しない。

Effect 2 — StateChange（持続・代償）

Trigger対象が個人試聴を開始し、そのセッションが継続している間。
Condition対象が当該セッションの開始者で、セッションが継続中であること。他のプレイヤーの試聴では発生しない。
Effect種別・結果StateChange。対象プレイヤーの移動入力、通常攻撃（素手のワンツー）、および装備4枠の他のスキル発動を受け付けない。硬直やStunは発生せず、入力が結果に届かないものとして扱う。カメラ操作とUI操作を残すかどうかは未確定。
対象・作用範囲試聴中の通常プレイヤー1人。範囲は個人。同一マップの他の参加者と店内の共有BGMには影響しない。
保存境界・終了保存境界は一時、解決はsustained。当該セッションの終了、マップ離脱、Run終了のいずれかで解除（end_mode: any）。試聴の既定時間を越えて残す理由がない。
重ね掛け例外なし。試聴を複数回行っても1件を保ち、残りの時間は更新しない。Stun、Down、SHADE、バックステップ、Roll、/dev/nullの入力無効化との順序は未定のため保留する。
Server / ClientServerがセッションの継続を検証し、封じ中の入力は既存経路でも例外なく不成立として扱う。クライアント側の無効化に依存しない。HUDには操作できない操作だけを表示し、理由の説明はしない。残りの時間の表し方は未確定。
Feedback成功: 封じに入った直後に操作が反応しない個人表示。失敗: 封じ中の入力には短い個人表示だけを返し、ワールド状態を変えない。不明: 封じが本スキルのためか別の理由によるものかを個人表示では区別しない。

Effect 3 — InformationChange（持続・記録）

Trigger上のRuleOverrideで個人試聴セッションが終了したのと同じ瞬間。
Condition対象がその試聴を開始し、そのセッション中に未閲覧の項目が1件以上残っていること。残りが0件なら生成しない。
Effect種別・結果InformationChange。対象プレイヤーの個人記録として未閲覧の項目1件だけを再閲覧できる状態にする。項目が持つのは名前と選択結果のみ。共有の店内状態、棚の検索状態、共有BGM、他プレイヤーの画面は変化しない。
対象・作用範囲記録を行った通常プレイヤー個人のみ。Party共有には展開しない。Serverは本人の保持の有無だけを保持する。
保存境界・終了保存境界は同一マップ中。1回再閲覧した時点で破棄。マップ離脱と、帰還・死亡・切断によるRun退出で破棄。マップを出て持ち越す記憶にはしない。
重ね掛け例外なし。保持は最大1件で2件目は上書きしない。2件目の扱いは本案では決めていない。Archive Selection UIの既存選択結果、Memory SwapperのLastRecognizedPlayerのような未実装の認識状態、共有BGMのServer Stateとの相互作用は未定のため保留する。
Server / ClientServerが記録対象の所属と、中断が本Effectによるものであることを検証し、未検証の項目指定は受け付けない。本人の個人記録にだけ項目名を表示し、座標、棚の構成、他プレイヤーの記録は表示しない。共有の店内表示にも出さない。
Feedback成功: 終了の直後に一度だけ記録が1件残ったことを示す個人表示。失敗: 未閲覧0件の時は記録しないと表示だけを本人に出し、ワールドも他プレイヤーの画面も変えない。不明: 残った項目が店内側の記録なのか本人が記憶として持っているだけなのかは表示で確定しない。
本候補はHealによるAnomaly Entityの鎮静、SHADEによる検知不能、cureによるExposureの解除のように、既存のタグを全アノマリーへ一般化した処理は一切含まない。Player Anomalyの専用攻撃や固有帰還にも触れない。

(d) 未確定事項・矛盾・世界観上の異化

未確定事項未閲覧項目のうちどの1件を候補にするか（選べる形式か規則で決まるか）。記録を残すと同じ棚の検索をもう一度開けるか。記録はセッション単位か棚単位か。記録した項目を再度開いたときに何を示すか。試聴中にカメラとUI操作を残すか。試聴機ではなく棚の検索だけで成立するか。他プレイヤーの試聴をどう扱うか。受付の封じとStun、Down、SHADE、Roll、/dev/nullの入力無効化の先後順序は未定義であり、書いていない。
既存仕様との矛盾1) anomaly-interaction.md「伝播、遮蔽、同期の方式は未決定」「BGMや通常の環境音が自動的に相互作用になるわけではない」。本案は音の伝播に依存せず、Server側のセッション開始と終了だけを入力にする。2) map-gimmick-ideas.md「項目は名前と選択結果のみを持つ」。本案は内容を作らず、再閲覧という到達だけを可能にする。
補正と理由1) 採用する場合、音の伝播、遮蔽、同期という未決定領域には手を入れず、試聴セッションの開始と終了という個別の文脈として記録する。共有BGMの選択UIは未実装のまま維持する。2) 採用する場合もメディアの実内容は追加せず、個人記録というUI層の事実だけを追加する。外部作品や商標の扱いは変更しない。
異化したもの試聴の自動終了を、視聴の期限ではなく何を1件だけ持ち帰るかを決める判断の期限として使うこと。試聴が聴くだけで終わる場面から、店内を去る前に一つ選ぶ場面へ変える点。
世界内の成立理由廃TSUTAYAのコンセプトはMediaとRealityの境界が崩れる原理を扱うとされ、媒体の実機能は未確定のまま残されている。本候補は現行の試聴機、PreviewDurationによる自動終了、Archive Selection UIという既存の手掛かりだけから成立し、店内側の記録の仕組みを新たに導入しない。既存システムの追加として成立し得る。
曖昧に残す意味残った項目が店内側の記録なのか、本人が記憶として持っているだけなのか。他プレイヤーに口頭で説明しても相手の記録が増えないのか、その差の意味は何か。いずれも確定しない。

世界観の自己確認: INV-01からINV-11の11項目すべてを確認済み。操作と終了条件は具体的に書き、店内側の記録の正体は仮説として留めた。実在のTSUTAYA店舗や外部作品、既存の製品名は流用していない。新たなルーム、通路、配置は提案していない。永続的な数値蓄積で優位性を決めていない。

(f) 新規ロジックと試作コスト

prototype_cost: 中 — 試聴機、アーカイブ棚、Archive Selection UI、PreviewDurationによる自動終了、共有BGMのServer Stateはすべて既存実装であり、組み合わせの変更は要らない。音響の伝播や遮蔽、Anomaly Entityの相互作用には一切触れないため、調整の範囲はUIとサーバー側の個人状態に閉じる。一方で新しいスキル発動経路と本人属性の保存先が必要で、既存の3スキルと同じ形にするかSkillServiceへ追加するかが未確定なので中とした。ここはゲーム内試作の見積もりであり、候補生成にかかった時間ではない。

試作工程: 1) 個人試聴の開始と終了がServer側のどこで処理されるかを確認する。2) 試聴継続中の移動と攻撃の入力を不成立にする状態を実装し、既存の移動とスキル経路と競合しないことを確認する。3) 試聴セッションの終了時に未閲覧項目を数え、1件だけ本人属性へ保存する。4) 記録された項目をArchive Selection UIから1回だけ開ける経路を追加し、消費後に消えることを確認する。5) マップ離脱、Run終了、未閲覧0件、連続した試聴のそれぞれで記録の扱いをログで確かめる。

想定する既存部品: TSUTAYAの試聴機と、PreviewDurationによる自動終了／Archive Selection UIの一覧、選択、閉じるという既存の遷移／共有BGMのServer State保持と、個人試聴がこれを変更しないこと／各ルームの配置規約（Listening Station、GimmickPoints、SpecialPoints）／既存3スキルのサーバー側発動とクールダウン。

レベル1試聴中に自分で中断でき、中断の瞬間に未閲覧の項目が1件だけ個人記録に残る。記録は1回で消費する。試聴中は移動、通常攻撃、他のスキル発動を受け付けない。保持できる項目は未閲覧のものに限る。
レベル2中断の前に残す項目を自分から選べるようにする。選べるのは未閲覧の項目1件だけである。候補を画面に出すか記憶で選ぶかは未確定。
レベル3記録した項目を、TSUTAYAの別の試聴機のセッションから1回だけ開けるようにする。保存境界は同一マップ中のままで、マップを離れると失われる。試聴1回につき記録は1件しか持てないという制限は変わらない。
装備4枠との関係探索系の1枠として扱う。4枠を何と組み合わせるかは本案では決めない。装備切替の場所とタイミング、および奥義、パッシブ、アノマリー専用スキルが枠を占有する条件は skill-build.md で未決定のため触れない。開錠と同一枠の競合は配置側の判断に委ねる。
通常攻撃との連携本候補は攻撃ではなく試聴の操作である。試聴中は移動も通常攻撃も他のスキルも受け付けないため、試聴中にワンツーからスキルへの連携を組むことはできない。試聴の外で組む連携は通常の規則に従う。
何を避けるか試聴中に無防備になることによる接近の危険を受け入れることで、無駄な戦闘を避けられる。試聴が自動終了して何も残らない結果も避けられる。ただし試聴そのものは防御手段ではない。
何へ介入するか個人試聴セッションの終了時刻と、Archive Selection UIで閲覧できる項目の個人記録。共有BGM、棚の検索集合、他プレイヤーの試聴、地図と備品の配置には作用しない。
何を犠牲にするか試聴中は移動、通常攻撃、他のスキルがすべて発動不能になる。記録は1件、単回、本人限定で、マップを離れると消える。残すために1件を選んだことで、同じ試聴に残っていたほかの未閲覧項目へアクセスする手段を失う。記録できる項目が0件なら何も残らない。
