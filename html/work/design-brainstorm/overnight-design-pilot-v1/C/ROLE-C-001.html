ROLE-C-001 巻き戻し地点（8/31・アクション系）

8/31のフェーズ遷移確定の瞬間だけ個人用の時間窓を開き、その窓で「前相でいた自分の位置」へ一度だけ自己を戻す。位置だけを戻すので、地形も帰還面もExposureもRun Lifetimeも巻き戻らない。戻った直後はそのフェーズの間、技能と通常攻撃が発動できなくなる。

(b) 設計仮説とプレイヤーの選択

設計仮説: 時刻のフェーズを「残り時間のカウントダウン」と同時に「前相の自分の位置を参照できる機会」として二重に使う。8/32が近づくほどRun Lifetime300秒の残り時間が短いので、往復距離の回収に価値が出るが、回収するとそのフェーズの間は戦闘も探索も選べない。

狙う体験

時計を注視せずに、自分の移動履歴から「今なら戻れる場所」を選ぶ判断。遷移の確定は共有事実として扱われ、個人側の操作だけが選ぶ。残り時間が短い局面ほど判断の重みが上がる。

判断と代償

窓内で発動するか見送るかで、そのフェーズを探索に使うか行動不能に使うかが決まる。戻す先は固定で選べない。戻した後は移動できるが4枠すべてとワンツーが沈黙する。ExposureとRun Lifetimeは減らない。

作用図 — フェーズ共有状態、アンカー記録、そして1回の消費

この図で分かること: 共有のフェーズ列と個人の記録列は別々に進む。記録は毎フェーズで上書きされ、消費すると消える。窓は遷移確定にだけ開く。戻った後の制限はそのフェーズ内にだけ残る。位置以外の世界の状態は戻らない。

図では確定しないこと: 窓の秒数、アンカー座標の精度、8/32遷移後に着地点が通行不能になった場合の挙動、封じが他の状態異常とどの順に適用されるか。図の左右配置は現実のマップ配置ではない。

(c) Trigger・Condition・Effectの契約

三つのEffectを分ける。位置の移動、遷移後の受付封じ、個人の記録保持は寿命も検証主体も異なる。

Effect 1 — Move（即時）

Trigger8/31の共有マップ状態が DAY→EVENING、EVENING→NIGHT、NIGHT→AUG_32 のいずれかへ遷移したことをServerが確定した直後。クライアントのローカル表示やフェーズ時間の推測は開始条件にしない。
Condition遷移確定から窓（仮称、秒数未定）以内。対象プレイヤーのCharacterが有効。前相アンカーが個人記録として残っている。アンカーが未記録、消費済み、マップ外、Character喪失のいずれかなら不成立。
Effect種別・結果Move。対象プレイヤーのCharacter位置を前相アンカーの記録位置へ移す。移動速度、向き、速度状態、カメラの向きは保持しない。地形、Parts、帰還面、出口端末は変更しない。
対象・作用範囲発動した通常プレイヤー1人。Player Anomaly状態からは発動不可。範囲は個人。Serverの共有マップ状態、Run共有フラグ、Quest進行、出現率には反映しない。
保存境界・終了保存境界は一時、解決はinstant。適用解決は遷移確定1回で完了し、以降のマップ更新で上書きされうる。アンカー記録は使用1回で破棄。マップ離脱とRun終了でも破棄。
重ね掛け例外なし。同一Effectと同一対象は非加算1件。1回の遷移で入力が重なっても1回だけ解決し、位置は最後の1回を採用。Roll、バックステップ、グラップリング、および8/32の強制帰還による移動との競合は解決規則未定のため保留。
Server / ClientServerが遷移確定の事実、Run参加、アンカー記録の存在、Characterの有効性を検証。不成立なら位置を動かす 않고、世界内フィードバックだけを返す。クライアントからの位置指定は受け付けない。移動演出と局所表示は個人クライアントのみ。
Feedback成功: 短時間の局所演出と、アンカー消費の個人表示。失敗: 窓が閉じた、または記録が無いという短い局所表示のみ、ワールド不変。不明: 着地点の地形の差異は説明せず、移動が成立したという事実だけ伝える。

Effect 2 — StateChange（持続・代償）

TriggerEffect 1のMoveが同じ遷移イベント内で解決した直後。Moveが不成立なら発生しない。
Condition同じ遷移でMoveが解決し、対象がその遷移時に本スキルの保持者であること。
Effect種別・結果StateChange。そのフェーズの間、通常攻撃（素手のワンツー）と指定1枠以外の装備スキルの発動を受け付けない。硬直やStunではなく入力が結果に届かないものとして扱う。移動は可能。
対象・作用範囲Moveが解決した通常プレイヤー1人。範囲は個人。PartyやRunの共有フラグには影響しない。
保存境界・終了保存境界は一時、解決はsustained。次のフェーズ遷移確定、マップ離脱、Run終了のいずれかで解除（end_mode: any）。終了時点をフェーズ進行に揃えるため固定秒数を持たせない。
重ね掛け例外なし。同一対象は1件を保ち、次の遷移まで解除時刻を更新しない。Stun、Down、Roll、/dev/nullのSkillとAttackの無効化、Mad StomperのHeal Fieldとの順序は未定のため保留。
Server / ClientServerが遷移確定とCharacter状態を検証。封じ中の入力は既存経路でも例外なく不成立。クライアント側無効化に依存しない。HUDには「どの枠が発動できないか」のみ表示し、理由と残秒は出さない。
Feedback成功: 発動直後に一度だけ、封じ中の枠が反応しない個人表示。失敗: 封じ中の入力に短い個人表示だけを返し、ワールド状態を変えない。不明: 封じが遷移由来かアノマリー由来かを個人表示では区別しない。

Effect 3 — InformationChange（持続・記録）

Trigger8/31の共有マップ状態がフェーズ遷移し、対象がその遷移をマップ内で迎えたとき。
Condition対象が当該遷移時にマップ内にいること。マップ外の対象には記録を作らない。
Effect種別・結果InformationChange。対象プレイヤーの個人記録としてそのフェーズでの現在位置をアンカーとして保存する。共有世界の地形、日付板、帰還面は変化しない。
対象・作用範囲その遷移をマップ内で迎えた各参加プレイヤー個人。Serverは記録の有無だけを保持し、共有HUDや他プレイヤーには見せない。
保存境界・終了保存境界は同一マップ中。使用1回、マップ離脱、Run終了（帰還、死亡、切断）のいずれかで破棄。地図に残るほど世界的な記録にしない。
重ね掛け例外なし。フェーズごとに1回だけ上書き保存し、フェーズ中に回数が増えても最新1件だけ。地図再生成や他の位置変更Effect、8/32のParts一括表示との相互作用は未定のため保留。
Server / ClientServerが遷移確定と対象の存在を検証し、クライアントからの位置報告は受け付けない。個人記録には「記録がある」ことのみを示し、座標、記録数、他者の記録は表示しない。共有の地図表現には出さない。
Feedback成功: 遷移後に短い個人提示のみ。共有側の表示は増やさない。失敗: マップ外では記録しない（前の記録は離脱時点で破棄済み）。不明: 記録位置が現在の地形とずれていても理由を説明しない。
この候補はcureの汎用解除、Exposureの操作、Player Anomalyへの状態変化を一切行わない。Anomaly Entityの全镇静や検知不能といった一般化も行わない。

(d) 未確定事項・矛盾・世界観上の異化

未確定事項窓の長さ（秒数）と窓の起点（遷移確定の瞬間か遷移後の準備完了か）。アンカーに記録する座標が遷移確定の瞬間か直前か。8/32遷移後に Parts が衝突したとき、アンカー位置が通行不能になった場合の着地処理（発動拒否／押し出し／落下ダメージ）。受付封じとStun、Down、Roll、/dev/nullの無効化、Mad StomperのHeal Fieldとの順序。個人記録をPartyへ見せるか。ワンツーからの連携の受付時間とキャンセル可能点（skill-build.mdで未確定）。4枠すべてがアクション系のフルアタック動作（未決定）との干渉。
既存仕様との矛盾1) skill-build.md「各系統のランク1はまだ3案に達していない」。本案はアクション系ランク1の3件目を提案する。2) current-implementation.md「現在サーバー実装されているスキルは3つで、ビルド取得・強化システムは未実装」。本案はこの経路がそのまま使えるとは主張しない。
補正と理由1) 採用時はアクション系ランク1が3案に達した旨を反映し、本案単独ではレベル3条件を満たさないことを併記する。既存のスキルの効果、数値、4枠の扱いは変更しない。2) 採用時は SkillService へ新しい発動種別を追加する必要があり、ビルド取得・強化の未実装部分と切り分けて記録する。既存のスキル経路や4枠UIの意味は変えない。
異化したものフェーズを刻む時計を、残りの時間としてだけでなく、前相でいた自分の位置という参照先として使う。8/32の帰還閉鎖とExposure 2.4倍、Run Lifetime300秒という脅しはそのまま残し、その中で自分の軌跡を再利用する操作を1つ加えた点。
世界内の成立理由本世界では物体の落下や名称による対象の区別など、人間の暗黙の想定から逸脱し得る、と定義されている。探索者が「さっきいた場所」を手掛かりに移動する観察手法はその定義の内側にあり、既存システムの追加として成立し得る。アンカーが世界の記録なのか個人の記録なのかは説明しない。
曖昧に残す意味前相の位置を参照できるのは、地形が記憶の結果なのか、時計が何かを戻した結果なのか、それとも別の理由なのか。8/32で地図が再構築された後に何が残るのかも確定しない。

世界观の自己確認: INV-01からINV-11の11項目すべてを確認済み。操作と終了条件は具体的に書き、原因と起源は仮説として留めた。現実の日本や実在のTSUTAYA、既存作品のプロパティは流用していない。マップ配置は模式図であり、地形や建物を提案していない。永続的な数値蓄積で優位性を決めているわけではない。

(f) 新規ロジックと試作コスト

requires_code: true — 必要な4経路（8/31のフェーズ遷移をServer側で購読する点、個人ごとのアンカー記録と1回消費、記録位置への自己テレポートと着地の検証、遷移後の発動受付の封じ）のいずれも current-implementation.md に実装記録がない。実装済みスキルはMagic Bolt、Roll，Stealthの3種で、ビルド取得と強化システムも未実装のため、既存のスキル発動経路をそのまま再利用できる根拠がない。trueは必要性の記録であり、コード生成の許可ではない。

prototype_cost: 中 — 8/31のフェーズ進行、地形生成、Lightingの差し替え、Run Lifetime、帰還面の開閉は既存実装があるため流用できる。既存部品にないのは遷移の通知点、個人の記録、着地の安全性検証、受付封じ状態の4点。地形は既存のまま使うため作り直しは不要。ただし検証ログ（記録された座標、封じ中の不成立件数）が必要で、中程度の試行を要する。ここはゲーム内試作の見積もりであり、候補生成にかかった時間ではない。

試作工程: 1) 既存フェーズ進行から遷移確定の通知経路があるかを確認。2) 個人にアンカー項目を持たせ遷移確定時に1件保存。3) 限定窓で発動すると記録座標へテレポートし、地形衝突時は発動拒否。4) 同遷移で受付封じが発火し、次の遷移確定・離脱・Run終了で解除されることを確認。5) 記録消費、離脱破棄、封じ中の不成立、8/32での着地不能をログで確かめる。

想定する既存部品: August31Serviceのフェーズ進行とServer側時刻進行／8/32専用Partsの非表示保持と一括表示／Run Lifetimeと帰還面の開閉処理／RollとStealthの既存発動とサーバー側クールダウン／Exposureの取得と閾値到達処理。

(g) 担当固有 — 系統・ランク・Lv1〜3・4枠・通常攻撃連携・回避／介入／代償

系統アクション（skill-build.md: 高速移動、Teleport、Grapplingなどの移動やギミックへの介入）
ランク候補値 1。アクション系ランク1は現在二段ジャンプと移動速度上昇の2案で、本案を3件目として扱う。各系統で次ランクを解放するには直前ランク3つ解放かつ1つ以上レベル3が必要という規則と、3案が3件目を満たすことによる帰結は conflicts に記載した。1を採らない場合も内容は成立する。
レベル1フェーズ遷移確定後の窓内で、自己の現在地を前相アンカーへ移す。アンカーは1回消費。遷移後はそのフェーズの間、移動以外のスキル発動と通常攻撃の受付が封じられる。窓の長さと着地の安全性は未確定。
