(b) 設計仮説とプレイヤーの選択

設計仮説: 協力PvE探索が前提とするその場の無音の一体感は崩さず、その上に、互いを認識できる音のある共同作業を1つ加える。待ち合わせの意図を音として残すことで、「本人だけが知っている意図」と「他の参加者にも観測できる意図」を同時に作り、特定のAnomalyに依存しない設計にする。

狙う体験

合図の手間と入力切り替えの手間が減り、連続行動の途中に発生させる判断の負担が下がる。窓を開いた事実はサーバー側の記録として残るため、個人の提示と共有の事実を分けて扱える。窓が開いたときに世界が応じるかどうかは、観察の余地として残す。

判断と代償

今この瞬間に連携を取るか、別の作業の優先順位を上げるか。窓を開けば、他のスキルは次の窓まで沈黙する。窓は同時1件で、時間は有限、次の窓をいつ開けるかは各自が決める。窓の開始は音として記録され、意図が他のプレイヤーと世界の双方に残る。

作用図 — 窓の開通、受付範囲、そしてサーバー記録として出た意図

この図で分かること: 窓は二人の間にだけ存在的で、サーバー記録は別系統である。個人提示とサーバー記録が分かれており、共有ワールドの表現は増えない。記録先であるアノマリー側の受理は一様ではなく、何も起きない場合も有効である。

図では確定しないこと: 窓の長さ、指名できる人数、連携できる入力の種類、音の種類と伝播、記録の保持期間、切断時の扱い。図の左右の位置関係はマップの空間関係ではない。

(c) Trigger・Condition・Effectの契約

三つのEffectを分ける。窓の状態、入力の拒否、サーバー記録は寿命も検証主体も異なる。

Effect 1 — StateChange（持続・窓）

Trigger対象が本スキルを発動し、同一Runの参加者を1人指名したとき。
Condition指名先が同一Runの参加者であること。対象がPlayer Anomaly状態にないこと。対象ごとに同時に開ける窓は1件で、すでに窓が開いている場合は発動しない。
Effect種別・結果StateChange。対象と指名先の2人が、この期間にだけ連携された入力を相互に受け付けられる状態になる。開通中に可能なのは指定した1枠のスキル発動と連鎖入力だけで、他のスキルと個別の通常攻撃は受け付けない。生命、装備、地形、共有ワールドの状態は変更しない。
対象・作用範囲発動した本人と指名した相手、合計2名。範囲は対象個人と指名した相手。Run全体の共有フラグやマップ状態には反映しない。
保存境界・終了保存境界は一時、解決はsustained。窓の長さが経過、マップ離脱、いずれかが戦闘不能、Run終了のいずれかで破棄（end_mode: any）。長さの秒数は未確定。永続的な合意や累積値は作らない。
重ね掛け例外なし。同一Effectと同一対象は非加算1件。対象ごとに同時1窓で、窓中の再発動は残りの長さを延長しない。同じ2人の競合窓の優先順位、および個別クールダウンとの先後関係は未定のため保留。
Server / ClientServerが指名先が同一Runの参加者であること、対象がPlayer Anomaly状態にないこと、既存の窓がないことを検証する。クライアントは窓の長さや対象を指定できない。窓の表示は対象と指名先の個人画面だけ。他プレイヤーの窓の有無は公開しない。
Feedback成功: 開通の瞬間に短い個人提示、以後はHUDに残りのみ。秒数の正確さは未確定。失敗: 指名先が不在または既存窓がある場合に、変化しないことを示す短い個人表示。不明: 相手が見ている側の表示に意味を与えず、本人の操作事実としてのみ提示する。

Effect 2 — RuleOverride（持続・受付の拒否）

Trigger窓が開通している間、対象または指名先がスキルまたは通常攻撃の入力をしたとき。
Condition窓が対象本人に開いていること。指定した1枠のスキルと連鎖としての通常攻撃は対象外とする。
Effect種別・結果RuleOverride。対象は対象プレイヤーの入力受付のみに限る。指定1枠以外のスキル発動入力、および連鎖の入力を受け付けない。個別のクールダウンやその他の判定より先に評価し、個別スキルの効果自体は発生させない。対象以外のプレイヤーの入力受付には影響させない。
対象・作用範囲窓が開いている対象と指名先の、各自のスキル入力と通常攻撃の受付のみ。範囲は対象個人と指名先。共有の入力処理や他の参加者の受付は変更しない。
保存境界・終了保存境界は一時、解決はsustained。窓が閉じた、マップを離れた、Run終了のいずれかで解除（end_mode: any）。恒久的に受付を狭めない。
重ね掛け例外なし。窓が1件なので重ねても1件を保つ。/dev/nullによるSkillやAttackの無効化、Stun、Down、Mad StomperのHeal Fieldとの適用順は未定のため保留する。両者が同時に成立した場合の扱いは決めていない。
Server / ClientServerが拒否対象の所属を検証し、拒否された入力を不成立として例外なく扱う。クライアント側の無効化に依存しない。HUDには窓が開いていることと、指定した1枠だけが発動可能であることだけを表示し、理由は出さない。
Feedback成功: 指定した1枠だけが発動できることを示す表示。失敗: 窓の開通中に押した入力は不成立として短い個人表示だけを返し、ワールド状態を変えない。不明: 選んだ枠が発動しない場合がクールダウンや静寂によるものか窓による拒否かを個人表示では区別しない。

Effect 3 — InformationChange（即時・サーバー記録）

Trigger窓が開いた瞬間、および閉じた瞬間。
Condition対象が窓を発動したこと、または窓が正常に終了したことを確認できたこと。不成立の開通では記録しない。
Effect種別・結果InformationChange。窓の開始と終了をSound Interactionの入力事実としてサーバー側で記録する。どのAnomaly Entityがその音を受理し結果として何を起こすかは、それぞれのアノマリー資料の定義に委ねる。本候補は記録を作るだけで、特定のアノマリーへの作用を保証しない。
対象・作用範囲記録先はサーバー側のSound Interaction入力の記録。個人への提示は窓を開いた本人と指名先のみ。Runの進行、出現率、マップの状態は変更しない。
保存境界・終了保存境界は一時、解決はinstant。記録の作成と提示で即時解決する。保持期間とマップやRunを越えた参照の可否、切断した参加者の記録を残すか、Run終了で破棄するか引き継ぐかはいずれも未確定。現時点ではRun終了で破棄する既定を置く。
重ね掛け例外なし。開窓1回につき開始と終了の記録を1組だけ作る。同時刻に複数の窓が開いても個別の窓ごとに1組。環境音やBGMと区別する手段、記録をwhisper、Mad Stomper、/dev/nullへ渡す際の優先順位は未定のため保留。共通ディスパッチを新設しない方針は変えない。
Server / ClientServerが記録の作成と、対象の所在、および指名先が参加中であることを検証する。クライアントから記録の書き換えも削除も受け付けない。本人と指名先の個人画面には短時間の提示を出す。共有のHUDや地図の表現に新しい情報は出さない。
Feedback成功: 窓が開いたことと閉じたことだけを短い個人表示で返す。失敗: 記録ができなかった場合は短い個人提示を本人にだけ出し、共有の画面には出さない。不明: 窓の音に何かが応じたかどうかは本候補は表示しない。応答の有無はアノマリー側の受理規則の決定事項である。
本候補はHealによるAnomaly Entityの鎮静を一般化せず、SHADEによる検知不能を一般化せず、cureによるExposureの解除も行わない。Exposure、Player Anomaly化、Quest進行、出現率変更には一切触れない。

(d) 未確定事項・矛盾・世界観上の異化

未確定事項窓の長さ（秒数）と全マップ共通で同じ数値を使うかどうか。指名できる相手は1人までか参加者全員か。連携として受け付ける入力の種類。窓を開いた音の種類と伝播、遮蔽、同期。同時成立の競合の優先順位。受付の拒否と、/dev/nullの無効化、Stun、Down、Heal Fieldとの適用順。切断と脱落時の窓と記録。複数人での検証（現時点は1人セッションのみ）。記録の保持期間とマップやRunを越えた参照の可否。奥義・パッシブ・専用スキルの枠占有条件が未決定であるため、指定1枠の扱いはそれらにとって未定義。指名する2人目がいない場合の方針。
既存仕様との矛盾1) anomaly-interaction.md「各アノマリーは Interaction Kind ごとに Ignore、Accept、Transform、Intercept、Reject のいずれかを採れる」「共通ディスパッチは現時点では新設しない」。本案は窓の開始をSound Interactionの入力として記録する。2) skill-build.md「装備切替の場所、タイミング、および奥義・パッシブ・専用スキルが枠を占有する条件は未決定」。本案は指定1枠の選択を要するため、枠の選択が成立するタイミングを前提にする。
補正と理由1) 採用する場合も個別の受理と結果はアノマリー資料側で定義し、共通ディスパッチを新設しない方針は変えない。矛盾の可能性があるのは記録した時点ですでに結果を示すように書いてしまう点だけである。2) 採用する場合も装備切替のタイミングと枠の占有条件は未決定のまま維持し、指定1枠をその場での選択に限る。装備の切替そのものは本候補に含めない。
異化したもの連携を無音の同時入力として扱う既定の考え方は崩さず、その上に互いを認識できる音のある共同作業を1つ加える点。協力PvE探索が前提とするその場の無音の一体感に対して、意図的に区切りを入れる。
世界内の成立理由音は既にAnomaly Interactionの入力種別として定義され、whisperも音響と認知へ干渉する。音が世界への入力として扱われているという前提に立てば、音の生じる共同作業は新たな仕組みを要求せずに成立し得る。音の意味や待ち合わせの用意された経緯は説明しない。
曖昧に残す意味窓を開いたときに何かが応じるのか、応じないのか。応じた場合でもどのアノマリーが何としてきたのかは語らない。博士の真意、組織の事情、起源には触れない。

世界観の自己確認: INV-01からINV-11の11項目すべてを確認済み。操作と終了条件は具体的に書き、窓の意味と音の起源は仮説として留めた。現実の日本や既存のプロパティは流用していない。判定地点や配置は提案していない。永続的な数値蓄積で優位性を決めていない。

prototype_cost: 中 — サーバー権威のRun状態、PlayerのAttribute、既存3スキルの発動経路は既存実装があるため流用できる。連携窓の状態、入力受付の切替、入力記録の3点が新規である。音の伝播や遮蔽、アノマリー側の受理規則には依存しないため、Effectの検証はサーバー側のログと個人画面の確認で足りる。複数人同時での競合確認は1人セッションでは検証できず、未確認の部分が含まれるため中とした。ここはゲーム内試作の見積もりであり、候補生成にかかった時間ではない。

試作工程: 1) デバッグフロアで同一Runの参加者を2人用意し、片方が窓を発動し、他方の入力を1回受け付けるまで実装する。2) 窓の開通中に指定1枠以外と連鎖の通常攻撃が不成立になることをサーバー側で確認する。3) 窓の開始と終了が入力として記録され、記録の書き換えと削除が拒否されることを確認する。4) 切断と戦闘不能で窓が破棄されることをサーバー側のログで確認する。5) 2人が同時に窓を開いたときの競合をログで記録する。複数人セッションが使えない場合は未確認として残す。

想定する既存部品: RunStateとサーバー権威のRun管理／PlayerのAttributeとHP、Run Lifetimeの状態保持／既存3スキル（Magic Bolt、Roll、Stealth）のサーバー側発動とクールダウン／既存の近接判定とExposureの取得処理（変更しない方針）／パーティ受付の上限5人と受付時の範囲判定。

(g) 担当固有 — 系統・ランク・Lv1〜3・4枠・通常攻撃連携・回避／介入／代償

系統補助（回復、Buff、Debuff、状態異常攻撃）
ランクnull。補助系のランク1にはヒール（仮称）とcureの2案があり、ランク2案には範囲ヒール（仮称）がある。ランク1の3件目として置くと同系統の構成が変わるため、系統構成が未確定である以上、根拠のない数値は置かない。順位の決定は採否の判断に委ねる。
レベル1同一Runの参加者を1人指名し、一定時間の連携入力受付窓を開く。窓の中では指定した1枠のスキル発動と連鎖入力だけが受け付けられ、他のスキルと個別の通常攻撃は不成立になる。窓の開始と終了がSound Interactionの入力として記録される。窓の長さと対象人数は未確定。
レベル2窓の中で連鎖として受け付けられる入力を増やす案。連鎖の入力受付時間とキャンセル可能点はskill-build.mdで未確定であり、この拡張を採用するかは別途決める必要がある。
レベル3指名できる相手を1人から同一Runの参加者全員へ広げられる案。同時参加者は最大5人で、全員に同じ権限を渡すとは限らない。対象人数の上限と切断、脱落時の扱いは未確定であり、記録の扱いは変わらない。
装備4枠との関係補助系の1枠として扱う。4枠を何と組み合わせるかは本案では決めない。装備切替の場所とタイミング、および奥義、パッシブ、アノマリー専用スキルが枠を占有する条件は skill-build.md で未決定のため触れない。指定1枠は使用時の選択に限る。
通常攻撃との連携本候補の窓は連携の受け皿であり、連鎖を発生させるものではない。窓の中では連鎖としての通常攻撃の入力を受け付け、連鎖ではない個別の通常攻撃は受け付けない。連鎖の入力受付時間、キャンセル可能点、硬直は skill-build.md で未確定であり、数字は置いていない。
何を避けるか連携のために必要な合図と入力切り替えの手間の一部と、2人の意図がずれたまま行動するリスクの一部。ただし窓は攻撃力を上げず、Anomaly Entityの追跡や攻撃の判断、博士のQuest進行には作用しない。
何へ介入するか同一Runの参加者2名の間でのスキル入力の受付と、サーバー側のSound Interaction入力の記録。マップ状態、Anomaly Entityの状態、出現率、Exposure、HP、帰還、Quest進行には作用しない。
何を犠牲にするか窓の開通中は指定1枠以外のスキルと、連鎖としての通常攻撃が発動できない。窓は対象ごとに同時1件で、長さは未確定であり、次に開ける時間は各自が決める。窓の開始は音として記録されるため、他のプレイヤーと世界の双方に意図が伝わる。音への受理はアノマリーごとに個別に定義されており、本候補は何も起こさないことも許す。
実在の身体技術挙げていない。実在の身体技法を根拠にしておらず、確認できた一次資料もないため、real_techniques は空配列のままである。既存の作品から技名や演出を借りて空白を埋めることもしていない。
