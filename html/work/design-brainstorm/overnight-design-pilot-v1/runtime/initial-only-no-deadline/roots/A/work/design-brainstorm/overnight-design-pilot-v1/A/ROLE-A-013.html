開いた通路の個体 — イベント由来の通常モブ

既存のギミックイベントが「開いた」状態をServerが確定し、湧き枠に空きがあれば通常モブが湧く。個体は進行方向を1つだけ持ち、終端で自然に消える。終端や速度、上限の数値はすべて未定。

見出しは作業用であり、正式System IDでもゲーム内名称でもない。Anomaly EntityでもPlayer Anomalyでもない。配置、地形、部屋は提案していない。

(b) 設計仮説とプレイヤーの選択

設計仮説: 選択中のマップで、既存のギミックイベントが1つ以上「開いた」状態をServerが確定し、湧き枠に空きがあれば、通常モブの個体が湧くと仮定します。個体は進行方向を1つだけ持ち、終端へ到達すると自然に消えます。戦闘を近づけても大量配置はしません。湧きは開いたイベントが閉じると止まりますが、残った個体は消えません。上限はServerがRun単位で持ち、Anomalyの同時出現数コンポーネントとは別の枠として扱います。個体数は上限内でしか補充しません。終端や速度、湧き方向、上限の数値は未定です。地形や部屋、配置は提案しません。

狙う体験

出来事が起きている場所と、個体が通る場所を分けて読む。戦わずにやり過ごす選択肢を必ず成立させる。湧き元のイベント名は出さないので、場所の変化だけを材料にする。

判断と代償

交わらない／先読みして迂回する／戦って個体対処する／イベントを閉じて湧きを止める（可否は未定）。回避はその場所で待つ時間を失い、報酬も得ない。戦闘しても湧き枠が埋まるまでは補充が続くため、局面は終わらない。

作用図 — 開いたイベント、湧き枠、一方向の個体、四つの退場

この図で分かること: 湧きは「イベントが開いたこと」と「枠に空きがあること」の両方が必要である。イベントが閉じると湧きだけが止まり、残った個体は終端まで進む。枠はAnomalyの枠と別である。

図では確定しないこと: 上限の数値、湧き方向、終端の定義、採用するイベントの種類、湧き先の通行。図は模式的であり、マップの地形や配置を確定するものではない。

(c) Trigger・Condition・Effectの契約

Effectは3件。湧き（世界変化）、接触Damage（即時）、終端での個体終了（即時）を分ける。

Effect 1: WorldChange持続（sustained）／保存境界: 同一マップ中／湧き枠の記録と個体出現
Trigger選択中のマップで既存のギミックイベントが「開いた」状態をServerが確定し、湧き枠に空きがある。
Condition開いたイベントが1つ以上存在すること。湧き枠が上限に満たないこと。対象マップが本候補の湧きを許可していること。イベントの種類、湧き周期、上限の数値は未定。
結果湧き指示がRun共有の枠へ1件記録され、通常モブの個体が出現する。個人へは何も表示しない。
対象・作用範囲対象: Run共有の通常モブ湧き枠と、湧いた個体。範囲: Run全体（選択中のマップ内）。個人ごとの所持や表示には作用しない。
保存境界・終了終了条件: 対応する開いたイベントが閉じた（湧きのみ停止。残存個体は消えない）／Run終了／マップ終了。いずれかが成立すれば枠の受付を閉じる（any）。個体側の終了は別のEffectで扱う。
重ね掛け例外ではない。1つの開いたイベントからの湧き指示はイベントごとに1件として扱い、回数で加算しない。異なるイベントが同時に開いた場合の枠の順序は未確定であり、自動合算も後勝ちもせず保留し記録する。博士Questの1.40倍補正、発生ごとの0.90倍減衰、Anomalyの同時出現数コンポーネントとは別の枠であり競合しない。
Server / ClientServerがイベントの状態と湧き枠の空きを検証し、個人側のクライアント信号では湧きを起こさない。Clientは個体の出現表現のみを表し、湧き元のイベント名、枠の残数、補充の予告は表示しない。
Feedback成功: 進行方向に個体が出現し通行がふさがる。失敗: 枠が上限に達している、またはイベントが閉じている場合は湧かない。判別不能: なぜこの場所で個体が出たのかは説明しない。
Effect 2: Damage即時（instant）／保存境界: 一時／個体との接触
Trigger個体が対象の接触範囲に入り、Serverがその接触を判定した。
Condition対象が個体の進行経路上にいること、個体が移動中であること。接触の判定方式と間隔は未定。
結果対象のHPを減少させる。数値は未定であり、プレイヤー間HP下限の規定を通常モブへそのまま適用しない。
対象・作用範囲対象: 接触した個人。範囲: 個人。同一Runの他の個人へは伝播しない。
保存境界・終了終了条件: このDamageについて適用解決した／接触が離れた（この時点で再度のDamageは発生しない）。即時効果としてイベントごとに解決する。範囲効果への拡張は定めない。
重ね掛け例外ではない。接触イベントごとに解決し重複して加算しない。他のDamageや状態異常との合成規則は共通既定が未解決であり、個別規則がなければ保留する。Player AnomalyとのHP下限の扱いは判断019に記載がないため未決として記録する。
Server / ClientServerが接触位置、個体状態、対象を特定して検証し、表示だけの接触はDamageを発生させない。Clientは接触の表現とHP表示のみ。個体名や種類は表示しない。
Feedback成功: 接触表現が出てHPが減る。失敗: 接触しない（回避できたことは成功ではなくプレイヤーの選択）。判別不能: Damageの由来は表示せず、回避しても得られる手掛かりは無い。
Effect 3: StateChange即時（instant）／保存境界: 一時／終端到達による個体終了
Trigger個体が進行方向の終端へ到達した。
Condition個体が存在し、移動中で、終端の判定を満たしたこと。終端の定義は既存の通行の末端を想定するが確定していない。
結果個体が終了し、湧き枠が1つ解放される。枠が余る場合は以降の湧き判定で補充の余地が生まれる。
対象・作用範囲対象: 終了した個体と、Run共有の湧き枠。範囲: Run共有。個体の終了はすべてのClientに表現されるが、枠の残数自体は表示しない。
保存境界・終了終了条件: この終了処理について適用解決した。個体ごとに1回だけ解決する。枠の解放が重複しないよう終了済みの個体には再度適用しない。
重ね掛け例外ではない。個体ごとに1件。同じ枠を別のEffectが操作する場合は共通既定が未解決であり、規則がなければ保留する。
Server / ClientServerが個体の到達と終了を検証し、破棄済みや未初期化の個体には適用しない。Clientは個体モデルの消滅表現のみ。解放された枠は表示しない。
Feedback成功: 個体が終端で消え通路上が静かになる。失敗: 終端へ到達できない場合は終了しない（終端の定義が未確定）。判別不能: 補充を待つことを知らせる表示は出さない。枠が空いたことによる変化は次回の湧きでだけ観測できる。

(d) 未確定事項・矛盾・異化と留保

未確定事項湧き上限の数値、枠の粒度（マップ単位かRun単位か）、補充の周期はすべて未定で、数値を決めていない。どのギミックイベントが湧きの条件になるか（8/31のフェーズ、TSUTAYAの放送、研究所の装置、SEKIGAHARAの戦闘イベントなど）、どれを採用するかは各マップ側の判断であり未確定。SEKIGAHARAはIdeaで勢力と戦況が未確定のため、同マップへ適用する場合の表現は別問題になる。進行方向と終端の定義は未確定。Player Anomalyとの間の個体HP下限は判断019に記載がなく未決。個体数が多い場合の性能影響は未検証。湧き方向が既存の移動経路と重なる場合の通行への影響も未検証。実装の有無はStudio未確認である。
既存仕様との矛盾2件をconflictsに記録している。（1）quests.mdの「同一マップ内でアノマリーが1体発生するごとに全候補の個別出現確率が0.90倍」に対し、本候補は通常モブの個体発生をこの回数に算入しない。（2）判断017の同時出現数コンポーネントに対し、本候補は通常モブにも枠を設けるが同じ枠へ統合しない。
補正と理由通常モブの発生をアノマリー出現の計算に算入しない旨を明記し、両者を別の計算として分ける。アノマリー側の減衰は通常モブの湧きに作用させない。枠はAnomalyの枠と判断017の意味をそのまま保ち、別枠としてRun共有に持つ。両方混在しても個体数の扱いは互いに影響させない。いずれも既存の意味を壊さないため補正可能と考える。
異化したもの異常空間ではなく、既存の出来事が動いた結果として個体が現れるようにした点が異化である。異常の正体を示さずに、場所の変化だけを戦闘の理由にする。名前も由来も示さないまま、通過すべき道と持久戦すべき場所を分ける。
世界内の成立理由舞台設定は、古い設備が現役で使われ、技術や生活習慣の更新速度が揃っていない文明を想定する。店舗が閉まる、装置が動く、時間帯が変わる、という出来事は日常的な場所でも起きる。それらが異常かどうかは答えず、個体が増えるという結果だけを見せる。世界の起源、アノマリーの正体、博士の真意には触れない。
曖昧に残す意味なぜその場所で個体が生じるのか。個体は何者なのか。出来事と個体の間に説明可能な関係があるかは提示しない。SEKIGAHARAの複数勢力のNPC戦闘とも別系統として扱い、本候補は一方向に通過する個体だけを扱う。

(f) 新規ロジックと試作コスト

requires_code: true — 既存のゲームには通常の敵AIの実装がなく、NPCStateはUnconfirmedである。Serverの湧き枠、上限判定、補充判定、個体の移動と終端判定、Damageの判定経路はいずれも新規実装を要する。既存のAnomalySpawnは未実装であり（判断017）、Anomaly Entityのプロトタイプを通常モブの根拠に使うことはできないためtrueとする。コード生成の許可ではない。

新規ロジック: Run共有の通常モブ湧き枠と上限、補充の判定／既存のギミックイベントが開いたことを表す共通状態とその入力からの湧き／個体の移動と終端到達による終了と湧き枠の解放／個体との接触Damageと、Player Anomalyを含む対象とのHP下限の判定／アノマリー発生回数と通常モブ湧きを分離する計算境界。

試作コスト: 中。 1種類の個体、進行方向1通り、枠1つという最小構成に限定すれば中程度。ただし湧き先の通行の選定、既存のPromptや地形との干渉、個体数の負荷、複数イベントが同時に開いたときの枠の競合規則は試作前に決める必要がある。SEKIGAHARAは未実装であり、既存2マップのどちらかに実装する場合でも共通設計の判断を要する。実時間の見積もりは出していない。

想定する既存部品: 既存のServer権威のRun状態とマップのライフサイクル／既存の通行（Trail、廊下）とマップ生成の骨格／既存のServer権威のPlayer Anomaly属性と判定（判断019）／既存のHPとDamageの受け口（HP属性は実装済み）。

(g) 担当固有（ROLE-A）の記述

NPCの目的個体は通常モブであり、依頼の担い手でも、アノマリーでもNPCでもない。目的として持つのは、既定された進行方向へ移動し終端へ到達することだけで、それ以外は設計しない。会話も説明もしない。世界や出来事の意味を語る存在ではない。
具体的な選択個体と交わらない位置取りで通過をやり過ごす／進行方向を先読みして迂回する／戦闘で個体対処する（枠が余る限り補充が続く）／開いたイベントを閉じる操作で湧きを止める（プレイヤー可能かはマップごとに未定）。回避を選んでも報酬は得ない。
Player Anomalyの扱い判断019によりPlayer Anomalyは通常NPCとInteractionできない。個体も通常NPCの枠に属するため、提示や受け渡しは成立しない。戦闘については判断019がPlayer Anomalyと通常プレイヤーとの相互キル許容を認めており、通常モブのHP下限は判断019に記載がないため未決として記録する。Player Anomalyの専用攻撃はPlayer Anomaly側の仕様であり、湧きの条件は変えない。
mob_contract: 適用spawn_condition: 選択中のマップで、既存のギミックイベント（8/31のフェーズ進行、廃TSUTAYAの放送やCRTの切替、研究所の装置の作動、SEKIGAHARAの戦闘イベントなど）のいずれかが「開いた」状態をServerが確定し、湧き枠に空きがあるとき。どのイベントが採用されるかは未確定であり未実装の機構も含む。Player Anomalyの発生や博士Questの受注、所持品は条件に含めない。／population_cap: ServerがRun単位で保持する通常モブの生存数に上限を設ける。数値、枠の粒度、補充の周期は未定で本候補では数値を決めていない。補充は個体数が減った分だけ枠内で行う案とする。Anomalyの同時出現数コンポーネントとは別の枠として扱い、同じ枠へ統合しない。博士Questの1.40倍補正、発生ごとの0.90倍減衰、アノマリー出現計算の対象にもしない。／non_combat_response: 個体は進行方向にのみ移動し終端で自然に消えるため、戦闘を避けられる。プレイヤーは交わらない、通過をやり過ごす、先読みして迂回する、イベントを閉じて湧きを止める、のいずれかを選べる。回避を選んでも報酬は得ない。回避は成功の手掛かりではなく選択である。／exit_condition: 4通り。（1）終端到達で自然消滅。（2）開いたイベントが閉じた場合は湧きのみ停止し残存個体は消えない。（3）戦闘による撃破はその個体だけを終了させ、枠が余れば補充が続く。（4）Run終了またはマップ終了で全個体を破棄する。個体の再開条件は定めない。／entity_distinction: 通常モブでありAnomaly Entityではない。特定のInteraction Kindを明示的に受理しない（受理表を持たない）。アノマリー相互作用の受理、拒否、変換、傍受のいずれも行わない。状態本体と寿命はServerの通常モブ枠で持ち、AnomalyのSystem IDを持たない。WorldChangeとして世界側の枠を操作するがAnomalySpawnの枠とは別である。SEKIGAHARAのIdeaに記載された複数勢力のNPC戦闘とは別系統である。
