02 ／ /dev/null — 入力と結果の断絶

Anomaly Entity。入力されたものを「存在しなかったこと」にする。 ゴミ箱・廃棄物のオブジェクトとしては描かない。本質は 入力 → 処理 → 結果 の因果対応が失われること。

(a) 根拠文書

docs/anomalies/dev-null.md（Status: Draft）: 入力されたものを「存在しなかったこと」にするアノマリー。 ゴミ箱や廃棄物を象徴するオブジェクトではない。 移動も攻撃もしない。近傍では攻撃、スキル、ダッシュ、ジャンプ、アイテム使用、インベントリ操作など、 プレイヤーが当然と考えるゲームシステムそのものの結果が到達しなくなる。 UI上では名前や画像が正常に認識できない、または欠損する表現を検討している。 通常の敵より強い警告を行うが、すべての結果を明示的に説明しない。 「何でも消す能力」ではなく因果関係の破壊が本質。 実装済みは距離判定、Tool無効化、結果無効化用Attributeとフィードバックまで（ダッシュ、ジャンプ、インベントリ操作、特殊スロットは未実装のDraft候補）。

docs/world/information-design.md / docs/anomalies/cognitive-anomalies.md: 実在の警告と誤認させるUIは使わない。详细を全部表示しない。

(b) 描画上の仮説

  1. 「物体」ではなく「欠落」で描く。この案では、/dev/null の存在自体を柱や玉のように描かず、結果が届かない輪郭だけで示す。中心には何も置かない。
  2. 破線は「切断された因果」。入力と結果の間の線を実線 → 破線 → 消えの3段階で描き、途中の受け皿は、結果がそこへ落ち続ける図として描く。
  3. UI欠損は「枠は残す」。アイコン枠・名前欄・数値欄の枠線だけを表示し、中身だけを空にする。枠ごと失わせると本質（入出力の断絶）と外れるため、枠は消さない案を仮置く。
  4. 警告は「近さ」で出す。文中どおり通常の敵より強い警告が必要なので、距離に応じて破線の数と円の濃さが増える表現を仮置き。警告テキスト自体は決めない。
  5. 特殊スロットは未実装のDraft候補として隔離。通常のインベントリ枠とは別枠・別色で「ここまでは壊さない」線引きを残す。
描かなかったもの: null化の範囲と優先順位（攻撃かスキルかアイテムか）、攻撃が通らない場合の正確な結果。 画面外のOS・実在の警告に似たものは一切描いていません。
