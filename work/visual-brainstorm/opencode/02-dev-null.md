## (b) 描画上の仮説

1. **「物体」ではなく「欠落」で描く。** 存在自体を柱や玉として描かず、**結果が届かない輪郭**だけで示す。中心には何も置かない。
2. **破線は「切断された因果」。** 入力と結果の間の線を「実線 → 破線 → 消え」の3段階で描き、途中の受け皿は結果が落ち続ける図とする。
3. **UI欠損は「枠だけ残す」。** アイコン枠・名前欄・数値欄の枠線だけを表示し、中身を空にする。枠ごと失わせると本質（入出力の断絶）と外れるため、枠は消さない案を仮置く。
4. **警告は「近さ」で出す。** 距離に応じて破線の数と円の濃さが増える表現を仮置き。警告文面は決めていない。
5. **特殊スロットは未実装のDraft候補として隔離。** 通常のインベントリ枠とは別枠・別色で、「ここまでは壊さない」線引きを残す。
6. **枠を消さないこと自体が本稿の中核仮説。** 「枠はあるが中身が無い」＝「入力は受け付けているのに結果が無い」という対応。

### 図の内容

- **図1 ／ 因果の断絶**: 入力（攻撃／スキル／アイテム／移動） → 断絶領域（半径未確定・結果が届かない） → 結果（発生しない）。断絶領域には実体・玉・箱を置かない。
- **図2 ／ UI欠損**: 通常時／近接時／特殊スロット（隔離）／警告（近さで濃く）。
