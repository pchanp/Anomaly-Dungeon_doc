(b) 設計仮説とプレイヤーの選択

設計仮説: 既存のDAMゾーンに、その場所の仕事だけを行う通常NPC（点検役）が巡回している。Serverは点検役の測定値をRunの事実として保持し、対象の測定条件を満たしている間だけ、その値を個人へ提示する。提示するのは測定値だけで、単位も基準も残り時間も出さない。点検役が攻撃を受けると巡回は止まり、最後の測定値だけが残る。地形、部屋、正式配置、新しい小物は追加しない。

狙う体験

観察したものが帰還判断の材料になる。ただし数字の読み方は説明されないので、Credibilityを自分で決める。記録は個人単位なので、同じフェーズでも全員の値は一致しない。

判断と代償

待つ（読む）／通り過ぎる／攻撃して止める。読むにはその場の時間を消費する。止めると記録源を失う。記録源を失っても資産の消費や固定ペナルティはないため、攻撃が常に最適解にはならない。

作用図 — Serverが記録を保ち、提示は個人、攻撃は記録源を止める

この図で分かること: 記録の保持、点検役の状態、個人提示の3段階が別である。攻撃は記録源を止める結果になり、進行自体を早めない。

図では確定しないこと: 測定周期、距離閾値、値の単位と意味、赤線と8/32の関係、配置座標、地形。図の縦軸は模式であり、地図や正式レイアウトではない。

(c) Trigger・Condition・Effectの契約

Effectは3件。1と3は作用先が個人、2はServer共有の個体で、状態を分ける。

Effect 1: InformationChange持続（sustained）／保存境界: 一時
TriggerServerが点検役の測定完了を確定し、測定値が存在し、対象が測定条件を満たしている。
Condition点検役が巡回中であること。対象が通常のプレイヤーであること。対象が測定条件を満たす位置にいること。測定間隔と提示範囲の閾値は未定。
結果個人HUDに最新の測定値を1行提示し、記録番号を併記する。世界側に刻まれる板や装置は追加しない。
対象・作用範囲対象: 測定値を閲覧する個人。範囲: 個人。Party HUDやRun共有表示にはしない。
保存境界・終了終了条件: 測定条件を満たす位置から離れた／点検役が巡回を停止した／マップから離れた／Run終了（帰還、死亡、切断、期限切れを含む）。いずれかが成立すれば閉じる（any）。
重ね掛け例外ではない。同一Effectかつ同一対象は非加算1件。再取得は残り時間を更新し、測定値は累計しない。別の情報提示Effectとの競合規則は本候補の範囲外であり、規則未定のため保留。
Server / ClientServerが対象個体、対象の属性、測定条件、巡回状態、測定値の有効性を検証し、不成立なら値を返さない。Clientは個人HUDの1行だけを表現する。
Feedback成功: 測定の所作とHUD更新が同期する。失敗: 近づいても更新しない。判別不能: 単位も基準も残秒も出さず、前回より値の向きが変わったことだけを読ませる。
Effect 2: StateChange持続（sustained）／保存境界: 同一マップ中
Trigger点検役が測点から次へ移動し、測定、記録、移動の一巡が完了した。
Condition点検役が巡回中であること。移動中の挙動は未実装のため、移動の区切りでのみ成立すると仮定する。
結果個体の状態が一巡完了へ移り、次の一巡を開始する。他プレイヤーの目には位置の変化としてだけ見え、測定値は共有されない。
対象・作用範囲対象: 点検役の個体（Server Run共有）。範囲: Run共有の個体。位置は全Clientに表現されるが測定値は個人。
保存境界・終了終了条件: 巡回停止へ移行／Run終了／マップ終了。停止からの再開は別個体の新規生成を要するものとし、同じ個体の一巡再開は定めない。
重ね掛け例外ではない。同一個体の進行はイベントごとに1件。同じ個体へ他の状態異常が重なる場合の順序は共通既定に従い、回復は本Effectの解除を意味しない。
Server / ClientServerが現在位置と巡回状態を検証し、未初期化または破棄済みの個体には遷移させない。Clientは移動表現のみ。移動速度、経路、測点の総数はUIに出さない。
Feedback成功: 一定時間測ってから次の測点へ動く。失敗: 測定中に次へ進まない（測定時間は未定）。判別不能:何を測っているのかは行動からは読めない。
Effect 3: StateChange持続（sustained）／保存境界: 同一マップ中／攻撃による巡回停止
Trigger点検役が攻撃を受け、対象のHP相当が減少した。
Condition巡回中でも一巡完了後でも、攻撃ダメージが一度でも成立した場合。ダメージ量の閾値は未定。
結果巡回を停止する。個体は測定と移動をやめ、最後の測定値を保持したまま現位置で静止する。以後の測定値は更新されない。
対象・作用範囲対象: 点検役の個体（Server Run共有）。範囲: Run共有。停止状態は他のプレイヤーからも観測できる。
保存境界・終了終了条件: Run終了／マップ終了のみ。回復しても再開しない（再開は別個体の新規生成として扱う）。
重ね掛け例外ではない。同一個体の停止は非加算1件。Stunなど別のEffectとの順序は共通既定に従い、回復は停止の解除を意味しない。
Server / ClientServerが攻撃ダメージの成立と対象個体を検証し、取り消された攻撃や対象外の攻撃では停止しない。Clientは測定の所作が止まる表現のみ。停止が仕様である旨の説明は出さない。
Feedback成功: プレイヤー側の成功は存在せず、記録源が止まる結果だけが返る。失敗: 攻撃が当たらなければ巡回は維持される。判別不能: 理由を示す文章を出さない。

(d) 未確定事項・矛盾・異化と留保

未確定事項測定周期、測点の順序、提示範囲の閾値、値の単位はすべて未定で、数値を決めていない。何を測るのか（堤防の水位か、日付板との関係か、別の量か）も未確定。記録が8/32の予告として読めるかも未確定であり、候補は予告としての位置づけを明示しない。8/32移行時に点検役が退場するか残るかは未確定。測定に時間を使う代償が帰還判断へどう影響するかは未検証。実プレイでの時間圧と、実装の有無は未確認（Studio未操作）。
既存仕様との矛盾3件を conflicts に記録している。（1）map-gimmick-ideasの「8/32の危険度上昇はExposureの取得速度と帰還閉鎖だけ」に対し、本候補は第三の先行手掛かりを足す。（2）判断003の「フェーズ長480/300/300秒は未確定」に対し、提示が残秒の手掛かりに読める危険があるため残秒を出さない。（3）current-implementationに通常NPCの状態機械が無いため、8/31マップ側か共通NPC基盤かを実装判断とする。
補正と理由危険度の表現はExposure速度と帰還閉鎖のまま維持し、候補は方向の手掛かりに限定する。残秒・基準時刻・測定間隔は表示せず、既存フェーズ長から導出しない。所有権は判断003がマップ固有に定めた段階進行の側に置く。いずれも既存の実装範囲と所有権を変えないため補正可能と考える。
異化したもの夏の光景を、依頼でも戦闘でもない一つの仕事として抽出し、その仕事の結果をゲーム内UIの進行バーではなく、個人がその場で読む一行動と一つの数値に置き換えた点が異化。異常を発生させず、情報源を人間の測定に結び付ける。
世界内の成立理由舞台設定は、高性能な機械の横にCRT端末があり、高性能な機械から紙の記録が出力される文明を想定する。測る、記録する、巡回する手順は、この場所が異常な空間へ変わっても成立する。崩れないからだけ、8/32へ進む段階変化が測れる差として表に現れる。
曖昧に残す意味なぜ値が段階的に変わるのか。点検役は誰が雇った人物で、何のために測っているのか。記録された値の正しい読み方は何か。8/32との関係は何か。いずれも痕跡として提示するが、世界設定としては確定しない。世界の起源、アノマリーの正体、博士の真意には触れない。

(e) 他担当への接続

接続タグ: Observation / NPCState / Environment / AugustPhase / Combat / InformationSharing

使用するコンポーネント: catalog: NPCState、Effect.InformationChange、Effect.StateChange、AugustPhase。proposed: NpcPatrolSchedule、PersonalHintDelivery。catalogのIDは記述語彙であり、StudioのComponent IDや実装Serviceを保証しない。

他候補へ提供できる性質: 既存のフェーズ進行を入力として受ける（段階変化の手掛かりとしてだけ使う）／Server権威の値を個人提示へ落とす／攻撃されないことを条件に挙動が変わる通常NPCが1体いる／残秒、単位、基準を表示しない手掛かりを構成できる。

予約参照ROLE-C-001（optional_connection、resolution: reserved_unresolved）。要求する性質: 回避判断の材料として提示できる（遠距離または非接触でも読める、または接近を避けながら読める）。代替: 接続がなくても、読む・通り過ぎる・攻撃して止めるは移動、攻撃、待機の既存操作だけで成立する。Cの候補が実在しない場合も、個人提示と巡回停止という結果自体は残る。
予約参照ROLE-B-001（optional_connection、resolution: reserved_unresolved）。要求する性質: 取得と所持を個人単位の状態として保持できる。代替: 測定値はアイテムにせず個人提示に留める。Bの候補が無くても成立し、記録は持ち帰れないままRunの事実として消える。
未解決の理由B-001: 正式なItemStackと取得源は未実装（SRC-01）のため、測定値をアイテムとして所持できるかは判断できない。C-001: Cの候補は管理側から配布されておらず、Cの001が何を定義するか不明。いずれも要求する性質の語彙だけを記し、相手の内容を創作していない。
ID未指定の要求個人提示を既存HUDへ載せるか専用UIにするか。測定条件を近接・視認・時間条件のどれにするか。いずれも候補IDでは特定できないため共通設計側の判断が必要（adoption_blocker: true）。
予約IDは未作成であり得ます。peer-snapshotsが管理側から配布されていないため、相手の本文を読んでいません。存在しないページへのリンクは置いていません。

(f) 新規ロジックと試作コスト

requires_code: true — 既存の8/31マップには通常NPCの状態機械、個人向け提示UI、測定の周期処理が存在しない。Server権威の測定値保持、個人提示の送信、攻撃による巡回停止という経路はいずれも新規実装を要する。外見だけの実装では値が個人ごとに違うこと、攻撃で記録が止まることが再現できないためtrueとする。これは必要性の記録であり、コード生成の許可ではない。

新規ロジック: Serverが保持する定点の測定値とその進行／測定値を個人HUDへ送る提示経路と残存管理／通常NPC個体の巡回状態機械と攻撃による巡回停止／測定条件（通常のプレイヤーであること、測定条件を満たす位置であること）のServer検証。

試作コスト: 中。 1体だけのNPCに限定すれば、Server側の巡回状態機械と個人HUDの1行表示で試せる。ただし通行、カメラ、Promptとの干渉、他マップのNPC案との共通化の要否、提示UIの設計は試作前に決める必要がある。8/31は地表タイルが1マップあたり約13,000 BasePartという記録があり（判断007）、その中での配置と動作確認は未確認。実時間の見積もりは出していない。

想定する既存部品: 8/31のServer側フェーズ進行（August31Service）とフェーズ別状態／8/32の帰還閉鎖、Exposureの取得速度2.4倍、Run Lifetime 300秒（実装済み）／既存のServer権威のPlayer Anomaly属性と判定／既存のマップ生成とPromptの骨格。

(g) 担当固有（ROLE-A）の記述

NPCの目的DAMの堤防で値を測るだけの点検役。目的はその場所の仕事であり、プレイヤーへの依頼でもクエ受理でも世界の説明でもない。world/information-design.mdが禁じる説明役を避け、会話で得られるのは今ここで何かを測っていることだけで、何がそうさせるのかには答えない。巡回の中断はプレイヤー側の入力の結果としてのみ起こり、世界設定とは切り離す。個体数は常に1体で、放置しても巡回は続くので放置でも成立する。
具体的な選択待つ（測定値を読む）／通り過ぎる（他の観察へ時間を回す）／攻撃する（巡回を止める）／別の用事を先に済ませる。いずれも結果だけが返り、正解の提示はしない。
Player Anomalyの扱い判断019によりPlayer Anomalyは通常NPCとInteractionできないため、測定値の取得は成立しない。巡回と測定はServerが続けるので、他の通常プレイヤーが読み取った値は他の個人の表示としてしか見えない。Player Anomaly自身が最後に記録を取り損ねた場合の扱い（記録が残るか消えるか）は未確定であり、地図の情報が全員分止まる扱いにはしない。
mob_contract: 対象外spawn_condition: 通常モブ敵の発生を含まない。イベントから通常モブが生まれる契約はROLE-A-013で扱う。／population_cap: 個体数は常に1体で、上限と補充の概念を持たない。湧き枠の扱いはROLE-A-013側だけに置く。／non_combat_response: 戦闘ではない。攻撃と回避はプレイヤー側のみで、NPCに攻撃の選択肢はない。／exit_condition: 退場は巡回停止、マップ終了、Run終了のみ。湧き、補充、自然消滅の機構を持たない。／entity_distinction: 通常NPCでありAnomaly Entityではない。受理するInteraction Kindは測定条件を満たす近接の観測のみ。巨人の状態実装も出現計算も根拠にしない。
