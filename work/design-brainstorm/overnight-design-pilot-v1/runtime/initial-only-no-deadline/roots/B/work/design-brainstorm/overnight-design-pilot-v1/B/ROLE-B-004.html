(b) 設計仮説とプレイヤーの選択

設計仮説: TSUTAYAには既に『個人試聴は個人にだけ聞こえ、共有BGMはServer Stateで管理される』という分離が実装済みで、『Back Roomなどで再生すると店舗のShared BGMを変えられる』という案も既にある。本候補はその案をそのまま再掲せず、媒体を1本の運べる品として個体化して、運んでから個人で聴くか共有回線へ出すかを先に選ばせる。取り出した側はRun中に何度でも試聴でき、共有へ出した側はRun中に戻せない。音の実体が未実装でも成立する経路で、個人提示とRun共有の世界状態の書き換えを同じアイテムの別操作として分離して示す。

狙う体験

この音を自分のものにするか、店全体のものにするかという媒体の扱い方を判断材料にする。共有へ出した瞬間から他者にも音が届き、出した本人にも撤回できない。试聴だけなら誰も傷まないが、その結果Run中に手元に何も残らない。

判断と代償

① 試聴機で個人試聴する（他者には何も伝わらず、手元に残り、あとで何度でも試せる）。② 共有回線へ出してRun全員に聴かせる（情報網は得られるが音源は説明できず、撤回も再選択もできない）。③ Secure Slotに入れて取り出さない（確実だが公開機会を捨てる）。④ 再生端末に触れず持ち出す（痕跡だけが残る）。失うのは、音源への接近権、他者との情報差、または共有での立場。

作用図 — 1本の媒体から分かれる2つの経路

左が所持。中央の上下で操作が分かれ、右上が個人提示、右下がRun共有の状態書き換え、その下に公開不可の消費がある。

この図で分かること: 同じ1本から個人提示とRun共有の状態書き換えが別操作として分岐すること、個人試聴は共有音に波及しないこと、公開すると媒体が個人から消えRun中に戻せないこと。

図で確定しないこと: どのRoomにどの端末を置くか、音源の種類、公開できる回数上限、上書きの可否、並行要求の解決規則。図は装置の配置図ではない。

(c) Trigger・Condition・Effectの契約

Effectは3件。InformationChangeが1件（個人試聴）、WorldChangeが1件（共有BGM差替）、StateChangeが1件（公開不可の消費）。WorldChangeは同一Run中の保存境界を持ち、Run終了で破棄する。

Effect 1: 個人試聴（InformationChange / sustained）

Trigger試聴機の前で、所持個人が対象の媒体を個人試聴として開始する
Condition対象のRoomに試聴機があり、対象媒体がServer上で操作者の所持品として存在する。試聴時間は実装済みのPreviewDurationに従い、個人側の上限を個別のEffectで増やさない
Effect種別・結果InformationChange。対象個体だけが個人枠で試聴できる。共有BGMは変化せず、他の個人のHUDにも共有BGMにも何も起こらない
対象・作用範囲操作した個人のみ（提示は個人に閉じる）。他者の聴取も共有Server状態も書き換えない
保存境界・終了同一マップ中／持続。PreviewDurationの経過または操作者による停止で個人提示のみ解除。マップ離脱またはRun終了で残りの個人提示も消える
終了規則end_mode: any。個人提示の寿命はマップ内に閉じる設計で、Run単位の共有状態とは別の境界に置く
重ね掛け同一個人と同一媒体の再試行は1件として扱い、残り時間を更新する。別媒体の試聴は別のEffectとして非加算で並行しうる。固定秒数の延長はしない。CRTのチャンネル変更や店内放送など別の音の経路と同時に成立する場合は、競合規則が未定義のため保留して記録する。個人試聴を常に優先させるルールは作らない
Server / ClientServerが対象の所在、Room内の試聴機の有無、試聴者のRun参加を検証する。個人提示の生成はServerが発行し、Clientの表示だけで他者の提示を作れないようにする
Feedback成功＝試聴中UIが始まり、終了時に終了表示。音の同定は提示しない。失敗＝試聴機が無いRoomや対象が無い場合は同じ不成立表示を1回。不明＝同じ媒体を試聴しても毎回同じ反応とするか変化させるかは未決。判断009にも既存案にも音の実体に関する記載が無いため、候補側で内容を作り出さない

Effect 2: 共有BGM差替（WorldChange / sustained）

Trigger対象の媒体を、共有BGMを差し替えられる経路（CRT、店内放送、共有再生端末）へ提示する
Condition対象個人がRunに参加中であり、対象のRoomに共有BGMを変更できる経路が存在する。個人試聴との同一視はしない。試聴機の個人試聴のみでは本Effectは成立しない
Effect種別・結果WorldChange。マップモデル直下の共有BGM（SharedBgmに相当するServer State）が差し替わり、Runに参加している他の個人の聴取内容が変わる
対象・作用範囲マップ共有のBGM状態（Server State）。Run全体。Runのすべての参加者が同じ音を共有する
保存境界・終了同一Run中／持続。別の媒体が共有へ出されたとき、または既定音源へ戻されたとき上書きされる。Run終了時に破棄し、マップ生成物とともに消える。マップ内の別室への移動では破棄しない
終了規則end_mode: any。上書きとRun終了は別の条件として列挙し、どちらも同一Run中の状態を終わらせる
重ね掛け同一Run中の共有BGMは常に1件。個人試聴は別Effectとして非加算で同時に成立できる。個人側の試聴回数で共有音を強くしない。別のEffectが共有BGMへ作用する場合は、解決規則が未定義のため保留して記録する
Server / ClientServerだけが共有BGMを差し替える。個人端末の表示状態や試聴履歴を根拠に差し替えない。差し替えの同時要求は1件に解決するが、競合時の規則は未確定として記録する。全員に新しい音が聞こえるが、何が選ばれたかを示す共有メッセージは出さない。発信者の位置や選択理由は個人にも共有しない
Feedback成功＝全員が同じ音を聞き始める。発信成功を示す個人通知を出すか、個数だけを示すかは未決。失敗＝経路が無いRoomや対象が無い場合は共有音変わらず個人に不成立のみ。不明＝他の参加者が何を出したかは共有音の変化から推測するしかなく、UIで説明しない

Effect 3: 公開不可の消費（StateChange / instant）

Trigger共有BGMへの差し替えがServerで確定した瞬間（WorldChangeの適用と同時）
Condition対象の媒体が個人所持からRun共有の共有音源へ移る状態になること。個人に同じ媒体が残らないことを同じ操作で保証する
Effect種別・結果StateChange。対象媒体が消費され、Run共有の共有BGMの音源として固定される。以後この媒体を個人側へ取り戻すことは永久に成立しない。不成立時に個人側の媒体は残る
対象・作用範囲対象の媒体1点と、共有へ出した個人。個人からRun共有の音源へ。個人側の所有権は失われる
保存境界・終了同一Run中／即時。差し替えが確定した時点で結果が確定。Run終了時に媒体データと音源が一緒に破棄され、成功帰還でも媒体は個人へ戻らない
終了規則end_mode: any。差し替えが不成立なら個人側の媒体は移動しないため、このEffectは発動しない
重ね掛け媒体1点につき1件。同じ媒体を2回共有へ出すことはできない。別の媒体は別のEffectとして順に適用できる。2人が同時に別の媒体を共有へ出した場合は、共有BGMは1件しか無いため一方しか反映できない。解決規則が未定義のため保留して記録する
Server / ClientServerが媒体が操作者の所持品であること、共有経路が存在すること、対象個人がRun中であることを検証してから個人側の媒体を除去する。除去と差し替えは同一の検証内で行う。個人HUDから媒体の所持表示が消えるが、共有された先や他者の反応は個人にも共有しない
Feedback成功＝所持リストから該当の媒体が消え、共有音が全参加者に届く。個人に公開したという説明文は出さない。失敗＝検証に失敗した場合は媒体が個人に残る。不成立表示のみ。不明＝Run終了時に消えた媒体がどこへ行ったのかは不明。破棄されたことだけを表現し回収先を示さない

他のEffectとの競合

本候補はアノマリー出現コンポーネント（個別出現確率・同時出現数）を変更しないため、博士Questの1.40倍補正や発生毎0.90倍減衰、判断017のRun単位変動と競合しない。一方、Sound Interaction一般の競合規則（anomaly-interaction.mdの未決事項）とは別に、共有BGMという単一の共有値へ書き込みが集中するため、同時要求の解決規則は候補側で確定していない。

(d) 未確定事項・矛盾・世界観上の異化

未確定事項音の同定ができない（実在の作品名・製品名・店名・曲名は使わない）。同じ媒体を二度試聴したときに内容が変化する場合の扱い。共有へ出した媒体を上書きで別音源に置き換えられるか、元へ戻せるか。同時に2人が共有へ出した場合の選択規則（先着順・投票・キュー）。離線と再接続時に何を復元するか。博士Questに載せるか。換金を別ルートとして扱うか。
既存仕様との矛盾なし。照合した範囲は判断010の枠強化、判断011のレアルート3系統とItem ID未決、判断014から016の博士Quest補正、判断021とeffect-componentsの効果分類と保存境界、map-gimmick-ideasの個人試聴と共有BGMの独立、判断009の配置と既存Prompt非改変。Robux変換経路はIdea（未採用）として扱い、矛盾はないと判断したため conflicts は空配列にしてある。
補正と理由矛盾がないため正本の書き換えは不要。ただし採用判断は1つ残る。既存の『Back Roomなどで再生すると共有BGMが変わる』案に、媒体の個体化と公開不可の消費を足すか、それとも既存案のまま媒体をRoomの固定设施として扱うか。前者なら判断010の入出庫未決との相互作用が生じ、後者なら Secure Slotの判断が成立しなくなる。
異化したもの試聴可能な音を観察するだけの行為から、媒体そのものを運んで公開するかを決める一回の資源へ引き下げた。試聴機は何度でも試せて所有物が変わらない装置、共有回線はマップの公開側を持つ装置、その間に運べる品が1点だけある、という三択を発生させた。
世界内の成立理由廃店舗化したTSUTAYAは誰も回収に来ないアーカイブとして扱われており、棚に残っているものは本来は閉店処理の行き場がない。探索者がそれを1本だけ持ち出して試聴の本人になるか店内へ戻すかは、そのアーカイブの持ち出され方として自然に成立する。世界側はアノマリーを完全に理解していないため、何が鳴ることを個別に説明する必要はない。
曖昧に残す意味その媒体が誰の手元から生まれ、誰が収納していたのか。共有音が何を指しているのか。共有が長く続いたことが何を意味するのか。博士の記録と繋がっていないのか。いずれも確定しない。共有が起きたことだけが明確で、誰が何をなぜ共有したかは説明しない。ダンジョンの起源や博士の真意の断定にも踏み込まない。

(f) 新規ロジックと試作コスト

requires_code: true — TSUTAYAのメディア項目は名前と選択結果のみを持ち実体が未実装であり、共有BGMの選択UIも未実装で現状は固定音源のループである。個人入力からServerの共有BGMを差し替える経路は実装済みでも設計済みでもないため true とする。個人試聴だけなら既存実装の上に成立するが、本候補の中核は共有への提示なので false とはしない。同時要求の解決規則は未確定であり、true の一部が未確定である。

試作コスト: 中 — 試聴機とCRTと共有BGMの枠組み、そしてServer Stateで管理される共有音は既に実装済みで、Archive Selection UIも名前と選択結果まで存在する。追加が必要なのは個人所持品から共有音を更新する1本の入力と公開不可の消費、そして提示UIの区別だけなので中程度。音の実体が未実装であるため試作では音の入れ替えを確認できず、名前と選択結果の表示変化だけを検証し実音の質には触れない。

必要な新規ロジック

  • 個人所持の媒体を、Serverが検証した上でRun共有の共有BGMへ差し替える入力経路。個人試聴の既存経路とは別の権限として扱う
  • 共有へ出した媒体を消費させ、Run中に個人へ戻せない状態遷移。戻せる場合は別設計とする
  • 同時要求の解決。複数の個人が続けて共有へ出した場合どの音を反映するか。規則は候補側で決めず未決として記録する
  • 離線と再接続時に個人試聴履歴と共有状態をどう復元するかの規則。判断012と同じ留保で未決

想定する既存部品

  • TsutayaGenerator（7ルームと通路。地形は増やさない）
  • TsutayaArchiveServiceとArchiveSelectionController（棚の検索UIと名前および選択結果）
  • 試聴機3台とPreviewDurationによる個人試聴の自動終了
  • CRT4台とチャンネルの切り替え
  • マップモデル直下に保持されServer Stateで管理される共有BGMのSound
  • InventoryServiceの枠境界（枠数は増やさない）

試作手順（ゲーム内試作コストの見積もりであり、生成に実際にかかった時間とは別）

  1. 既存のデバッグ付与で媒体1本を渡せるようにする。正式な取得源は未実装なのでデバッグで代用する
  2. 既存の共有BGM（Server Stateで管理されているもの）に対してServer管理の一時差し替え口を設ける。固定音源のループはそのまま残す
  3. 対象Roomの共有再生経路で個人所持の媒体を提示すると、Serverが所持と経路とRun参加を検証してから差し替える
  4. 差し替え確定と同時に個人側の媒体を除去し、Run中は戻せないようにする
  5. 試聴機での個人試聴は既存のPreviewDurationのまま動かし、共有音には触れないことを1人で確認する
  6. Play Soloの1人セッションで、個人試聴が共有BGMを変えないこと、提示で共有音が変わること、提示後に媒体が戻せないことを確認する。複数人の同時提示と切断は今回確認しない

item_kind: 未確定 — TSUTAYAのメディアは『発売されていない作品・存在しない作品が混在する』アーカイブ対象であり、レアルート品として博士研究室で永続強化に交換する用法を本候補では作っていない。判断011の3系統にそのまま載せるか、通常探索品として扱うかは採用時に判断する。Robux変換経路はIdea（未採用）であり本候補はこれにふれない。

AcquireProposed — 判断009が「返却作業場へカートと未整理ケースを追加する」と定めた配置先に回収する案を置く。既定の棚からの取得は別候補で扱って競合を避ける。未整理ケースの正確な座標は判断009のStudio確認待ちであり、候補では確定しない。
HoldProposed — 1枠を消費し、Secure Slotと枠を取り合う。試聴しない限り効果がないため、Secure Slotへ入れて死亡に備えるか、通常枠に残して共有へ出す機会を残すかの判断。试聴は複数回可能なので消費しないが、共有へ出した場合は消費される。スタック規則は未確定。
UseProposed — 使用が2つある。試聴機での個人試聴（個人提示のみ、共有音は不変、PreviewDurationで自動終了）と、共有再生経路への提示（WorldChangeとして共有音を差し替え、個体内で不可逆の消費）。1本の媒体でどちらの操作にも使える。
PresentUndecided — 誰が買うのか、誰が要求するのかが未確定。古物商やコレクターや店内放送の誰かへ渡す筋は考えうるが、TSUTAYAマップ内にも都市ロビーにも該当する人物は未実装であり、候補側で人物や組織を創作しない。
PlaceProposed — 本候補の中核。対象のRoomにある共有再生経路へ媒体を提示し、Run共有のBGMを差し替える。新たな装置は増やさず、既存の装置に操作口を与えるだけにする。個人試聴と同じ口で処理しない。
LoseProposed — Run終了時にSecure Slot外なら通常の喪失物。共有へ出した媒体は共有音に吸収された状態でRun終了とともに消え、成功帰還でも個人へ戻らない。放置して棚へ戻す操作は痕跡としてのみ扱う案で、獲得物にはしない。
SecureSlotProposed — 核心的な判断。Secure Slotに入れると死亡に耐えられるが、Run中の共有提示はできなくなる。逆なら提示の可能性はあるが失敗時に消える。Secure Slotへの入出庫時点自体が判断010の未決事項であり、本候補はその未決に確定を与えない。
SellUndecided — 判断010・判断011・経済と成長はいずれもレアルート品と換金の関係を未決のままとし、本候補はレアルート品への分類を主張しない。換金可能にすると「共有へ出すかどうか」という判断の重みが消えるため、採用時に換金を別ルートとして扱うかは要判断。
QuestUndecided — 依頼主と依頼種別が未確定。博士Questに載せる場合は相互作用成立時の固有品（判断012）と経路が重なるため、置かない判断も保留する。特定の音を店へ持ち出すことを依頼とする案は、依頼の成立条件ではなく世界情報の配布になるため別設計とする。
AnomalyInteractionNotApplicable — TSUTAYAマップ固有の異常は未実装であり、本マップにはアノマリーEntityの受理先が無いため、本候補をAnomaly Interactionとして作らない。共通Anomaly System導入後にアイテム操作の無効化やアイテムと認識の干渉と競合しうることは未決として別項目に記録する。
ownership_state（個人所持）試聴前の媒体はplayer単位の個人所持で1枠。個人試聴は所持を変えない。共有再生経路へ提示してWorldChangeが確定した瞬間に媒体は個人からRun共有の共有音源へ移り、個人側の所持表示から消える。個人HUDは操作提示のみを担い、共有音源の内容や他者の聴取状態を個人には表示しない。切断と再接続時の個人所持復元は未決。
server_run_state（ServerのRun状態）共有BGMはServer権威のRun状態として保持され、Runのすべての参加者が同じ音を共有する。個人入力がこの状態を書き換えるが、その前にServerが所持と経路とRun参加を検証する。Run終了で破棄し、マップ内の別室への移動では破棄しない。WorldChangeのEffectであり、保存境界は同一Run中。この候補はアノマリー出現コンポーネントを変更しないため、博士Questの1.40倍補正や発生毎0.90倍減衰とは競合しない。
