ROLE-B-001 預け札（帰還面脇のRun枠外置き場）— 作業用見出し

(b) 設計仮説とプレイヤーの選択

設計仮説: 既存仕様が持つのは『Secure Slot 4枠＋総20枠』という単一の保険枠だけで、失敗時の損失をどう割り振るかを設計する余地が狭い。本案はRun内に『成功を前提にして初めて効く置き場』を一段だけ足す。要素は『帰還面脇の預け札』であり、8/31で帰還面が既に開いている時間帯にだけ機能する。置いた品はRun中には使えず、帰還面が閉じた8/32では回収もできなくなる。Secure Slotが『死んでも残る枠』であるのに対し本候補は『生還して回収できたときだけ効く枠』である。枠外容量を与えて誘惑を持たせるが、中身はRun終了まで触れない、という二重の代償を設計の核に置く。

狙う体験

EVENINGでの『もう帰る』と『もう少し見る』の境目に、新しい判断材料を置く。Secure Slotへ入れた品と預け札へ置いた品が、8/32へ進むかどうかで別の結果へ分かれることを、直前の選択として感じさせる。安全を永続成長で買わず、その場の時間指定で買う構造にする。

判断と代償

① 帰還面の脇で預ける＝枠外へ逃がす。ただし使えず、8/32へ進むと回収不能。② Secure Slotへ入れる＝死んでも残る。ただし枠を1つ永続消費。③ 通常枠のまま運ぶ＝両方使えるが枠を圧迫し、失敗時は消える。④ 捨てる。EVENINGに①を選んだ場合、その後8/32へ進むかどうかが実質的な第二判断になる。失うのは、中身の使用機会、枠の永久消費、そして生還という前提そのもの。

(c) Trigger・Condition・Effectの契約

Effectは3件。StateChangeが2件（預け・取り出し）、InformationChangeが1件（個人提示）。WorldChangeは発生させない（出現率・同時出現数を変更しないため）。複数Effectは表を分けている。

Effect 1: 預ける（StateChange / instant）

Trigger帰還面が既に開いている状態で、所持個人が帰還面の脇で『預ける』操作を行う
ConditionRunがACTIVE、帰還面が既に開放済み（DAY中は不成立）、対象品が個人のインベントリ内、預け簿の枠数上限内。枠数上限は未確定
Effect種別・結果StateChange。対象品の所在が個人インベントリからRunの預け簿へ移る。以後その品は個人が使用できず、アノマリー相互作用の入力にもならない
対象・作用範囲対象の品1点と操作した個人。個人からRun共有の保存先へ所在を移す
保存境界・終了同一Run中／即時。Run終了（成功・失敗・切断、8/32のRun Lifetime満了を含む）で預け簿ごと破棄。帰還面の閉鎖（8/32遷移）は破棄ではなく『取り出し不可』にする
終了規則end_mode: any。既定。2条件は別々の性質を持ち、Run終了が唯一の破棄条件。両方成立時に片方だけを破棄扱いにする例外は定めない
重ね掛け同一品への重複『預け』は成立しない（もう一方のRun共有側に所在するため）。別の品への預けは非加算1件のまま累積。固定秒数は持たない。別Effectが同じ品に所在変更を要求した場合は解決規則未定義のため保留し記録する
Server / ClientServerがRun状態・帰還面の開閉フラグ（既存 ExitUnlocked に相当）・所有物・枠数上限を検証し、不成立時は状態を一切変更しない。Clientは操作可否の表示のみ
Feedback成功＝品が足元から消え、HUDの『預け中』印が1つ増える（確定音なし）。失敗＝操作が反応せず同じ不成立表示、理由の文章は出さない。不明＝印の意味を説明する文は出さない

Effect 2: 取り出す（StateChange / instant）

Trigger帰還面が開いている状態で、預け札の個人操作として『取り出す』を行う
ConditionRunがACTIVE、帰還面がまだ開いている（8/32遷移後は不成立）、対象品が当該個人の預け簿にある、空き枠が個人インベントリに存在
Effect種別・結果StateChange。対象品の所在が預け簿から個人インベントリへ戻り、その個人が再び使用できる。Secure Slotへは入らない
対象・作用範囲対象の品1点と操作した個人。Run共有の預け簿側だけが書き換わる
保存境界・終了同一Run中／即時。入出庫の1操作が解決した時点で結果は確定。Run終了で預け簿が破棄された後は対象が存在せず条件は恒久に不成立。切断時の再接続後の所属移動は未決とし、Serverは個人をまたいだ所在移動を許可しない
終了規則end_mode: any。解決済みの操作は再適用対象外。破棄後の再試行は対象不在という不成立として扱う
重ね掛け1操作1件。回数・時間制限は持たない。上限を設ける場合は同じEffectへの明示的な例外として本文に書く。別の操作と同時に成立する場合はServer側で同一フレーム内の二重解決を拒否するが、優先順位の規則は未確定
Server / ClientServerが帰還面の開閉・対象品がこの個人の預け簿に属すること・空き枠を検証する。個人HUDの表示回数やクライアント要求を根拠に所在を移動させない。Clientは操作可否と結果表示のみ
Feedback成功＝印が減り通常のインベントリ枠表示が1つ増える（確定音なし）。失敗＝印が減らず注意表示が1回だけ出て、理由の区別は日本語で出さない。不明＝8/32遷移後に印が残った状態は、失敗なのかまだ取り出せるのかをUIで区別しない

Effect 3: 個人提示（InformationChange / sustained）

Trigger預けまたは取り出しが成立した、あるいは不成立になったあと、Run情報HUDが個人状態を再描画する
Condition対象個人がそのRunの参加中で、Run情報HUDの表示が有効なとき
Effect種別・結果InformationChange。『預け中の品がある』ことを示す印と、最後の操作が成功だったかのみを更新する。内容・個数・総量は個人にも出さない
対象・作用範囲対象個人のみ。共有のRun状態は書き換えない
保存境界・終了同一Run中／持続。Run終了またはHUD非表示で解除。切断で個人提示は破棄し、再接続時に復元するかは未決
終了規則end_mode: any。HUD表示と個人状態の寿命は結びついているため別規則を定めない
重ね掛け同一個人への同一提示は非加算1件。残り時間を更新せず状態を上書きする。既存のRun情報HUDやQuestObjective表示と競合する場合、表示枠の優先順位が未決定なので強制作業しない
Server / ClientServerは預け簿が空か空でないかだけを返す。総量や内容は返さない。HUDの描画権限はClient側の表現に限る。他者のHUDに同じ印を出さないことで個人提示であることを明確にする

他のEffectとの競合

本候補はアノマリー出現コンポーネント（個別出現確率・同時出現数）を変更しないため、博士Questの1.40倍補正や発生毎0.90倍減衰、判断017のRun単位変動と競合しない。WorldChangeのEffectは発生させていない。異なるEffectが同じ品や同じ枠へ作用する場合の解決規則は未定義であり、競合適用は保留して記録する。

試作手順（ゲーム内試作コストの見積もりであり、生成に実際にかかった時間とは別）

  1. InventoryServiceの枠データに、Run内で消える第三の所在を1つ持たせる。永続枠は増やさない
  2. 8/31の既存帰還面脇に、預け操作のプロンプト1個と取り出し操作のプロンプト1個を置く。地形は増やさない
  3. Server側で帰還面が既に開いているかだけを条件に、預けと取り出しを検証して即時に所在を移す
  4. Run終了時に預け簿を破棄し、破棄済みの品を既存のリザルト獲得物と喪失物の分類へ割り当てる。分類処理自体は変えない
  5. HUDに『預け中の品がある』印だけを出す。個数と内容は出さない
  6. Play Soloの1人セッションで、DAY中は預けられないこと、8/32遷移後に取り出せないこと、死亡時に全品が喪失物になることを確認する。複数人と切断と再接続は今回確認しない

(g) 担当固有の経路・制約

item_kind: 通常探索品 — 汎用スキルレアルート品でもスロットレアルート品でもアノマリー固有交換品でもない。博士研究室で永続強化へ交換する用途を持たせず、Run内での置き場そのものを価値にする。Robux変換経路はIdea（未採用）であり、本候補はこれにふれない。

AcquireUndecided — 誰が配るかは未確定。8/31には通常NPCと施設と依頼発行者が未実装であり、人物や組織を創作しない。判断011の取得経路（相互作用成立・低難度以外のQuest・チュートリアル）のどれに載せるかを決めるまで条件は決めない。試作のみデバッグ付与で代用する。
HoldProposed — Run中は通常どおり使用できる品なので1枠を消費し、Secure Slotと枠を取り合う。8/32のRun Lifetime 300秒とExposure 2.4倍の下では、残り時間のために枠を空けたい圧力と、預けたい圧力が同時に出る。スタック規則と上限は未確定。
UseProposed — 使用が2つある。帰還面の脇で預ける（個人からRun共有の保存先へ所在を移す）と、取り出す（Run共有から個人へ戻す）。どちらも帰還面が開いている間だけ成立し、8/32遷移後は成立済みの預けについても取り出しが恒久に不成立になる。
PresentNotApplicable — 受け取る側の人物と機関を8/31文脈で確定していない。博士へ渡して永続強化へ交換する用法は判断010と判断011が既に定めるレアルート品の経路と二重になるため、本案では受け渡し先を創作せず対象外とする。
PlaceProposed — 本候補の中核。帰還面の脇という既存の共有装置の周辺に置き、Runの共有状態を更新する。新たな地形・部屋・装置は提案しない。DAY中は置いても効果が生じない、という条件不成立そのものが判断材料になる。
LoseProposed — Run終了（成功・失敗とも）で預け簿ごと破棄する。失敗時はSecure Slot内の物だけが獲得物になるため、預けた品は全部喪失物になる。成功時は回収済みの品のみ獲得物、8/32へ進んで回収不能だった品は獲得物にならない。切断と再接続時の所属移動は未決。
SecureSlotProposed — 核心的な競合点。預け札をSecure Slotに入れて死亡に備えると、死んでも残る手段の中に生還者だけが回収できる手段が混ざる。Secure Slotは確実だが枠を1つ永続消費し、預け簿は枠外だが8/32で効かなくなる。どちらに何個入れるかはプレイヤーのリスク選択であり、既定最適は作らない。
SellNotApplicable — 換金しない。博士研究室へ渡して成長資源へ交換する経路へ戻すと判断010と判断011が既に定めた経路と二重になり、枠外容量という本候補の性格が崩れる。回収物として価値がありそうなことは痕跡としてWorldにだけ残し、価格は決めない。
QuestUndecided — 依頼主と依頼種別と報酬額はいずれも未確定。博士Questの枠へ置くと受注中の出現確率補正と衝突するため、置かないという判断も保留する。判断014が定める固有品と専用スキルの交換とも別系統であることを明確にしないと経路が混線する。
AnomalyInteractionNotApplicable — 8/31は共通Anomaly Systemが未実装で、判断017のAnomalySpawnもNotImplementedであるため、本マップにはアノマリーEntityの受理先が存在しない。よって本候補をAnomaly Interactionとして作らない。将来の予約アノマリーが出現した場合に必要な例外ルールはAnomalyInteraction側のUndecided項目として別途残す。
ownership_state（個人所持）預け札そのものとRun中の個人所持はplayer単位の個人状態。預け操作の瞬間から対象品だけ所在が個人を離れ、ServerのRun共有である預け簿のentryへ移る。HUDに示すのは本人だけの印で、所在の確定はServerが行う。再接続時に所有者のいない品として扱う規則は未決。
server_run_state（ServerのRun状態）預け簿はServer権威のRun状態を保持し、個人とは共有しない。Run開始で空、Run終了（成功・失敗・切断・8/32のRun Lifetime満了）で破棄する。出現率と同時出現数というアノマリー出現コンポーネントはこの候補では変更しないため、WorldChangeのEffectは発生させずStateChangeとInformationChangeのみとする。破棄時にのみ既存のリザルト分類へ割り当てる。
