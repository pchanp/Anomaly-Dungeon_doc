(b) 設計仮説とプレイヤーの選択

設計仮説: 判断010の未決事項に、Secure Slotへの入出庫時点という項目がある。現状の実装は枠を増やして失敗に備えることだけで、Runの途中で自分の持ち物を出し入れする経路は無い。本候補は、枠は増やさずにRun中の入出庫を1回だけ許可し、その対価としてExposureを1段上げる設計を提示する。安全を1段買うたびに異常性へ近づくため、効果の代償を数値ではなく関係として示す。数値の上がり幅ではなく、残り1回を誰に分けるかという取り合いだけが設計の中心になる。

狙う体験

死んだ時に何を守っていたかという判断を、Runの途中でも組み直せるようにする。そのために異常性へ近づくという产品价格を明示し、自由に保険が買える構造にしない。

判断と代償

① 使う（Run中に1回だけ出し入れできる。Exposureが1段上がる）② 使わない（Exposureは上がらないが、Run中は枠を組み替えられない）③ この札をSecure Slotに入れて死亡に備える（確実に残るが、確保した手段が1つ減る）④ 捨てて枠を空ける。判断019のPvPと閾値設計が未実装のため、①と③のどちらが安全かは数字では示せない。

作用図 — 枠・例外操作・対価の関係

上が現状の3つの置き場（枠は増えない）。中央が1回だけ許可される例外操作。その下に操作の対価としてのExposure。底下は帰還時の既存の分類と、本札をSecure Slotへ入れたときの自己言及的な代償。

この図で分かること: 枠数が一切増えないこと、例外操作は1回だけで毎回上行かないこと、対価が個人内部状態（Exposure）に上乗せされること、成功・失敗の帰還分類は既存の規則のままであること。

図で確定しないこと: 段という単位の意味、上限の値、操作入口の場所、異常化の閾値設計、PvPの下限変更の影響。図はSecure Slotの構造図でも価格表でもない。

(c) Trigger・Condition・Effectの契約

Effectは3件。RuleOverrideが1件（1回だけの例外操作）、StateChangeが1件（対価としてのExposure上昇）、InformationChangeが1件（残り回数の個人提示）。WorldChangeは発生させない（出現率と同時出現数を変更しないため）。

Effect 1: Run中の入出庫を1回だけ許可（RuleOverride / sustained）

Trigger所持個人がRun中に、Secure Slotの出し入れ操作の許可を求める。入口は専用端末か所持時の操作かで未確定
ConditionRunがACTIVE、対象品が個人インベントリまたはSecure Slotのどちらかに存在、移動先が枠数制約を満たす、対象個人の残り操作回数が1以上。初期値は1で、回数の単位は未確定
Effect種別・結果RuleOverride。通常存在しないRun中のSecure Slot入出庫というゲームルールを、対象個人に対して1操作だけ許可する。枠数は増えず、Secure ConversionともCapacity Expansionとも無関係
対象・作用範囲対象の品1点と操作した個人。同じ操作を通った他の個人にもRun共有の枠にも波及しない
保存境界・終了同一Run中／持続。許可された1操作が解決した時点で例外は解除。Run終了で破棄し、マップ遷移では保持しない。対象品がSecure Slotの外で喪失した場合は以降が入出庫は対象不在として不成立
終了規則end_mode: any。例外としての存続は1操作の解決までで、Run終了が強制的な破棄条件。2つを別規則に分ける理由がない
重ね掛け例外：同じEffectへの再適用は例外として扱い、2枚目でも操作回数だけを1増やさない。残り回数を非加算1件に保つ。固定秒数は持たない。/dev/nullのような結果傍受系のEffectや個々のアノマリーによるアイテム操作の無効化との優先順位は未定義であり、候補側で適用順を確定せず保留して記録する
Server / ClientServerがRun状態、移動対象が対象個人の所持物であること、枠数制約、残り操作回数、操作者IDを検証する。クライアントの要求回数や表示だけを根拠にしない。クライアントは操作画面の可否と結果表示のみを担う。残り回数は本人だけに1回と表示し、他者HUDには出さない
Feedback成功＝枠の表示が1つ移動し、残りの表示が0になる（確定音なし）。失敗＝枠も残り回数も変わらず注意表示が1回だけ出、理由の区別は日本語で出さない。不明＝残り回数が0になった後で操作口が出ても、回数不足なのか権限不足なのかを区別しない

Effect 2: 対価としてのExposure上昇（StateChange / instant）

Trigger上のRuleOverrideの1操作が解決したのと同時に、対象個人の状態としてAnomaly Exposureを1段上げる
Condition対象個人がRunに参加中で、Exposureの上限を判定できること。上限の有無と値は未確定
Effect種別・結果StateChange。対象個人のAnomaly Exposureが1段上がる。HPは変化しない。異常化へ至るかどうかは閾値設計次第であり、候補側では確定しない
対象・作用範囲対象個人（Exposureという個人内部状態）。個人。Run共有のアノマリー出現計算は直接書き換えない
保存境界・終了同一Run中／即時。上昇の記録は即時に確定。Run終了でExposureの状態は次のRunへ持ち越さない
終了規則end_mode: any。即時記録とRun終了による状態リセットは別の条件として列挙する
重ね掛け同じ操作から来る上昇は1操作につき1段。固定秒数を持たない。既に記録済みの対象への再上昇を加算とするか置換とするかは候補側で決めない。他のアイテムや状態から同じExposureへ作用する場合も解決規則が未定義のため保留して記録する。8/32のExposure取得速度2.4倍という既存実装との合算順序も未確定であり、自動合算にしない
Server / ClientServerがExposureの現在値と上限を判定して更新し、クライアントが提示した値を書き込まない。クライアントは既存のExposureの個人表示が更新されるのと同じ経路を使い、本候補独自のHUDは増やさない。段という単位はUIに出さない
Feedback成功＝既存の個人表示が更新されるのみ（本候補に特有な通知は出さない）。失敗＝上限に達している場合は上昇せず、操作の表示だけがRuleOverride側で変わる。不明＝上昇した結果がどの判断へ近いかを示す表現は出さない。既存仕様に従い、候補で説明しない

Effect 3: 残り回数の個人提示（InformationChange / sustained）

Trigger本候補を所持している間、または1操作が成立したあと、個人HUDが状態を再描画する
Condition対象個人がRunの参加中で、個人HUDの表示が有効なとき
Effect種別・結果InformationChange。残り操作が1回であることを示す印を表示する。使用済みか未使用かのみを示し、枠数や内訳は出さない
対象・作用範囲対象個人（提示は個人に閉じる）。共有のRun状態は書き換えない
保存境界・終了同一Run中／持続。Run終了またはHUD非表示で解除。切断で個人提示は破棄し、再接続時に復元するかは未決
終了規則end_mode: any。HUD表示と個人状態の寿命は結びついているため、別規則を定めない
重ね掛け同一個人への同一提示は非加算1件。残り時間を更新せず状態を上書きする。既存のRun情報HUDや他のアイテム提示と競合する場合、表示枠の優先順位が未決定なので強制作業しない
Server / ClientServerが残り操作回数が1か0かを返し、内部の累積値は返さない。HUDの描画権限はClient側の表現に限る。小さな印を1つだけ提示し、他者のHUDには出さない。印の説明文は表示しない
Feedback成功＝印が点いた状態のときだけ再描画される（初回は1回だけ）。失敗＝不成立時は印が変化しない。不明＝印の意味は本人だけが判断する。ゲームは数字で安全性や有利さを保証しない

他のEffectとの競合

本候補はアノマリー出現コンポーネント（個別出現確率・同時出現数）を変更しないため、博士Questの1.40倍補正や発生毎0.90倍減衰、判断017のRun単位変動と競合しない。競合の可能性があるのは Exposure への別の作用（他のアイテムや状態）と、結果傍受系のEffectである。いずれも解決規則が未定義のため、候補側で確定せず保留して記録する。

(d) 未確定事項・矛盾・世界観上の異化

未確定事項Exposureの1段という単位そのものを設計していない（既存仕様に段という表現は無い。意図的な近似）。残り操作回数1回の初期値と対象範囲。Run中の操作入口が専用端末か所持時か。/dev/nullなど結果傍受系との評価順。判断019とcurrent-implementation.mdの満了処理の差。PvPの下限変更による影響。判断010の未決「入出庫時点」に対する他の解（Run中の入出庫を認めない方針など）。
既存仕様との矛盾docs/decisions/011-real-route-acquisition.md（Status: Accepted）「汎用スキルレアルート品（博士の過去の研究成果から抽出した汎用スキルの獲得と強化）、スロットレアルート品（Secure Conversion と Capacity Expansion）、およびアノマリー固有の交換品（対応する専用スキル）の3系統を定義する。」／ 本案は枠数を増やさずRun中の入出庫タイミングだけを可能にする消費品を、Secure Slotの運用に作用的レアルート品として置こうとする。Secure ConversionやCapacity Expansionの消費品ではない。
補正と理由判断011の3系統自体は変更しない。本件をスロット系の別系統として追記するか、新しい系統を立てるかは採用判断とする。枠数を増やさず永続強化の枠を消費しないため、判断010が除外している別種のスロット強化には該当しないと判断している。判断010が列挙から外しているのは枠数を増やす永続強化の追加であり、Run内の一時的な運用緩和ではないため。
残る採用判断本件を判断011へ追記するか、新しい分類を立てるか。どちらを選ぶかによって配布経路と消費内容の記述が変わる。
異化したもの保険を恒久的な道具として買うのではなく、Runの中で自分の持ち物を組み替える操作そのものを1回だけ売る形にした。安全を1段買うたびに異常性の側へ一歩進むため、効果と危険が同じ方向に並ぶ。ゲームはどちらが安全かを数字では返さない。
世界内の成立理由既に Secure Conversion と Capacity Expansion という、危険な資産を確保できる状態へ変える操作が設計済みであり、それをRunの中で使う不便さは既存の世界観と矛盾しない。世界側はアノマリーを完全に理解していないため、この道具の正体ではなく手順だけを教える。判断010が描く研究者像とも矛盾しない。
曖昧に残す意味入出庫札が誰の手で後から作られたのか、何のためにあったのか、1回という限界が物的条件なのか運用上の都合なのか、博士の主張と関係するのかは確定しない。残り1回だけが明確で、意味は説明しない。博士の真意やダンジョンの起源は断定しない。

試作手順（ゲーム内試作コストの見積もりであり、生成に実際にかかった時間とは別）

  1. デバッグ付与で入出庫札1個を持たせる。正式な取得源は未実装なのでデバッグで代用する
  2. InventoryServiceにRun中の枠移動操作を1つ足す。枠数の増加とSecure Conversionの処理は変更しない
  3. その操作の残り回数を個人単位に1回だけ保持し、操作成立時にExposureの個人値を更新する
  4. HUDに残り操作が1回か0回かの印だけを出す。段や内訳は出さない
  5. Play Soloの1人セッションで、操作が成立すること、枠数が変わらないこと、Exposureの表示が更新されること、残り回数が1回だけであることを確認する
  6. 複数人、切断と再接続、異常化と満了の扱いは今回確認しない

(g) 担当固有の経路・制約

item_kind: スロットレアルート品 — Secure Slotの運用に作用的レアルート品として扱う。ただし判断011はスロットレアルート品を Secure Conversion と Capacity Expansion の消費品と定義しており、本件はそのどちらにも当たらない。分類を維持するなら「スロット系の別系統」としての追記が必要で、その判断は採用側に残す（conflicts 参照）。汎用スキルレアルート品でもアノマリー固有交換品でもない。Robux変換経路はIdea（未採用）であり本候補はこれを設計していない。

AcquireUndecided — 判断011の取得経路（相互作用成立、低難度以外のQuest、チュートリアル）のどれに載せるか未確定。効果の重さを考えるとチュートリアル配布は保留。博士Questの枠へ載せると出現確率補正と経路が重なるため、その判断も採用側に残す。
HoldProposed — 1枠を消費する。相対的な希少さは方針としてだけ持ち、数値と確率は未確定。ここでは3つ目の判断が生まれる。他の重要品とこの札と本当に安全な場所へ入れる物の3枠を取り合うことになる。
UseProposed — 使用が1つある。Run中に1回だけ、対象の品1点をSecure Slotと通常スロットの間で移動する。残り操作回数を使い切れば同じ操作は二度と成立しない。入口が専用端末か所持時の操作かは未確定。
PresentNotApplicable — 受け取る側の人物と機関を確定していない。都市ロビーの研究室へ渡すのは博士の過去の研究成果を渡す交換であり、本候補は使用型の消費品として研究室での交換先を持たない。受け渡し先を創作せず対象外とする。
PlaceNotApplicable — 置き場を設けない。置けるようにすると Secure Conversion の枠を交換する契約と二重になり、またどこに置いたかが新しい所在管理を必要とする。試作時はデバッグ端末の操作口だけで実装する。
LoseProposed — Run終了時にSecure Slotの外なら喪失物。Secure Slotに入れていれば残るが、その1枠は他の重要品へ譲ることになる。切断と再接続時の扱いは未決。
SecureSlotProposed — 核心的な判断。この札をSecure Slotに入れて死亡に備えるか、通常枠に残して対価を払って使うかの二択になる。前者は確実ですが残す手段が1つ減り、後者は安全になりますが異常性へ近づく。どちらが合理的かは数字では出ないため、ゲームは既定の正解を提示しない。
SellUndecided — 換金可能にすると、対価を払って安全を買う構造がただの回収素材へ緩むため換金しない方向を推奨するが、Item IDと換金額は判断011で未決なので採用判断として残す。本候補は換金にも博士研究室での永続枠への変換にも置かない。
QuestUndecided — 依頼主と依頼種別が未確定。博士Questに載せる場合は相互作用成立時の固有品（判断012）と経路が重なるため、置かない判断も保留する。判断014の固有品交換と明確に別系統であることを示す必要がある。
AnomalyInteractionUndecided — 本候補はアイテム操作であり、Anomaly Interactionの分類のうちItem Interactionの範疇にある。ただし /dev/null のアイテム使用の無効化のような傍受系との評価順が未定義で、anomaly-interaction.mdの未決事項と直結する。採用時に順序を決める必要があり、候補側では決めない。対象とする既存アノマリーは未実装のものは含めない。
ownership_state（個人所持）入出庫札はplayer単位の個人所持で1枠。Secure Slotへの出し入れは対象の品についてServerが検証してから、個人インベントリとSecure Slotのどちらか一方の枠へ移す。所有権そのものは移動しない。残り操作回数は個人ごとのRun単位の状態であり共有しない。HUDに示すのは本人だけの印で、回数はServerが確定する。切断と再接続時の個人所持と回数の復元は未決。
server_run_state（ServerのRun状態）残り操作回数はServer権威の個人Run状態として保持し、他の個人には共有しない。Run終了で消え、次のRunでは初期値に戻る。本候補はアノマリー出現コンポーネントを変更しないためWorldChangeのEffectは発生させず、RuleOverrideとStateChangeとInformationChangeのみとする。8/32のExposure取得速度2.4倍との合算順序は未確定であり、自動合算にしない。
