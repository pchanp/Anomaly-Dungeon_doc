# whisper

**Status: Draft（草案）**

この文書は、音響・認知へ干渉し、特定の対象に付き従う `Anomaly Entity`、`whisper` を定義する。博士の元同僚Quest、相互作用の結果として残る装置、専用スキル `anxiety`、Quest完了後の出現候補解放を一つの連鎖として扱う。

| 項目 | 内容 |
| --- | --- |
| Game Name | `whisper` |
| System ID | Unconfirmed |
| Type | Anomaly Entity |
| 主な相互作用 | Sound、認知的フィードバック、攻撃しないこと、NPCへの追従先移送 |
| 専用スキル | `anxiety` |

## 概要

`whisper` は、不可解な音声・台詞・ゲーム内の選択UIによって、プレイヤーの認知を揺らすアノマリーである。分かりやすい怪物表示やジャンプスケアではなく、「いま表示されたものは何だったのか」をプレイヤーに判断させる。

`whisper` 自体は Invisible だが実体を持ち、移動する。出現時に決まった特定プレイヤーへ付き従う。見えないことは「存在しない」ことを意味しない。

## 音響・認知的な作用

`whisper` は、対象プレイヤーに対して不可解な台詞や音響、選択肢を伴うゲーム内UIを発生させ得る。内容は、プレイヤーやPartyに疑念を向けさせる指示、ゲーム外の操作を促すように見える指示、文脈のない選択肢などを含み得る。

- 右上の Signal UI は、`whisper` の作用を断定しない最小限の反応を返し得る。
- HUDで `ANOMALY DETECTED` のように答えを直接示さない。
- 表示はすべてゲーム内の演出UIとする。実際のOS、Robloxクライアント、ブラウザを操作させる・終了させる・外部へ誘導するUIにはしない。
- 固有名詞、既存作品の台詞、既存作品の画面演出をそのまま再現しない。

これは[認知アノマリー](cognitive-anomalies.md)の「異常を見せること」より「認識する行為」を扱う方針と接続する。ただし、視野レイキャストによる `Observe` を必須条件にするかは未決定である。

## 非攻撃・非選択による対処

付き従われたプレイヤーは、一定時間、攻撃アクションを行わず、表示された選択UIを選ばないことで、`whisper` の表示消失カウントを進められる。

- 選択UIを選ぶと、次のUIが表示され、消失カウントがリセットされる。
- 攻撃アクションを行った場合、非攻撃という対処条件は成立しない。カウントをリセットするか、別の結果を起こすかは未確定とする。
- 表示が消えることは、`whisper` を撃退・解決・報酬獲得したことを意味しない。

プレイヤーが「選ばない」「攻撃しない」を能動的な判断として扱うための設計であり、ポップアップを消すこと自体を正解入力にしない。

## 追従先の移送

`whisper` は、付き従っているプレイヤーが指定NPCへ接触したとき、そのNPCへ追従先を移せる。この移送が `whisper` に対する主要な Anomaly Interaction である。

追従先の移送後、元のプレイヤーへの音響・認知的な作用をどう停止・遷移させるか、移送中にPartyへどこまで共有されるかは未決定である。

## 博士の元同僚Quest

研究所マップには、博士と過去に共同研究をしていた元同僚がいる。元同僚は、アノマリーを制御・分析することそのものへ疑問を抱き、考え方の違いから博士のもとを去った人物として扱う。なぜその人物がダンジョン内の研究所で研究を続けているのかは説明しない。

プレイヤーが元同僚と会話すると、この人物に関する博士Questを受注できるようになる。博士は元同僚への不満を示しつつも、追従するアノマリーを本人に見せることを依頼する。ただし、元同僚を殺すこと自体は目的にしない。

Quest中の最小進行は以下とする。

```text
元同僚と会話し、博士Questを受注
  ↓
研究所マップで whisper に付き従われる
  ↓
whisper を伴った状態で元同僚へ接触する
  ↓
whisper の追従先が元同僚へ移る
  ↓
元同僚が恐怖し、研究機材へ閉じこもる
  ↓
研究機材を開くと、元同僚と whisper は消え、装置だけが残る
  ↓
Quest達成。装置を博士へ渡す
  ↓
博士は装置の正体を説明せず、「危険だから処分する」として回収する
  ↓
anxiety を獲得する
```

装置は、Quest報告の通常報酬ではなく、`whisper` の追従先移送という相互作用から残る関連アイテムとして扱う。博士へ渡す場面は、関連アイテムを専用スキルへ交換する演出である。装置の正体、元同僚と `whisper` がどうなったか、博士が実際に処分するかは不明のままにする。

Partyで成立した相互作用からの固有品配分は、[アノマリー相互作用](../systems/anomaly-interaction.md)のParty配分方針に従い、成立時のParty全員を対象にする。研究機材・装置を誰にどう表示するかは未確定である。

## 専用スキル: anxiety

`anxiety` は単なる精神攻撃ではない。対象の中に `whisper` を発生させ、その囁きが対象の内側から作用するようにする専用スキルである。これは現実の診断や心理状態を再現するものではなく、アノマリー相互作用として対象に発生するゲーム内の状態・現象として扱う。

| 対象 | 基本的な結果 |
| --- | --- |
| 通常NPC | 内側の `whisper` を不快音のように感じ、気味悪がる・嫌悪感を示す反応に留まる |
| 潜在要素を持つNPC | 隠していた要素、秘匿された状態、保留されていたエピソードが引き出され、個別設計された変化を起こし得る |
| 対応Anomaly Entity | 内部状態・隠れた性質・他の相互作用条件が表面化し、個別設計された相互作用を受理し得る |
| 博士 | `whisper` は成立しない。博士は迷いなく自分を信じており、通常NPCの不快音反応も、潜在要素を引き出す変化も起こさない |

ここで引き出されるものは、HUDが答えとして列挙する情報ではない。会話、行動、環境変化、別の相互作用などの痕跡からプレイヤーが推測できるようにする。`anxiety` を単純な正解表示、全対象に通用する行動妨害、または通常NPCへの万能な会話解決手段にはしない。

どのNPC・Anomaly Entityが潜在要素を持つか、対象内に発生した `whisper` の持続・可視性・重ね掛け・対人使用可否は未確定とする。

## 他マップへの出現解放

この元同僚Questを達成すると、`whisper` は研究所マップ以外のマップでも出現候補になる。これはマップ抽選の結果を変えるものではなく、選ばれたマップ内における `whisper` の候補可否を更新する進行である。

ソロでは、候補解放はQuest達成者自身の進行として扱う。Party Runでは、開始時Party内にこのQuestを達成した実績を持つプレイヤーが一人でもいれば、サーバーはそのRunにおいて `whisper` を研究所マップ以外の候補にも加える。したがって、解放実績を持たないプレイヤーも、他マップでの初遭遇として `whisper` に出会い得る。

Quest受注中に掛かる個別出現確率の1.40倍補正と、Quest達成後の他マップ候補解放は別の状態である。前者はRun開始時にサーバーが固定する確率補正であり、後者はPartyの解放実績からRun開始時に確定する候補可否である。各マップでの基礎出現確率、出現不能とする例外マップ、途中切断後の候補状態、再受注・再発生条件は未決定である。

## 実装上の注意

- 対象プレイヤー、追従先、Quest進行、関連アイテム、スキル交換、Partyの解放実績に基づくマップ候補解放はサーバーが確定する。
- 音響、Signal UI、選択UIはクライアントへ局所的に提示し得るが、選択結果・カウント・Quest進行をクライアントだけで確定しない。
- NPC接触は距離・対象・Quest状態をサーバーで検証する。
- `Sound Interaction`、`Skill Interaction`、`Environment Interaction`、NPCへの追従先移送の契約は[アノマリー相互作用](../systems/anomaly-interaction.md)に沿って個別に定義する。
- UIは不安を演出しても、プレイヤーの実環境を壊す操作や、実在の警告と誤認させる動作を行わない。

## 未決定事項

- System ID、対象プレイヤーの選定規則、同時に存在できる `whisper` の数。
- 攻撃アクションが非攻撃対処を破ったときの正確な結果。
- 台詞・音響・選択UIの具体的な文面、頻度、表示時間、アクセシビリティ設定。
- 追従先がNPCになった後の見た目・音響・Partyへの情報共有。
- 元同僚Questの正確な解放条件、Quest目標UI、失敗・再挑戦の扱い。
- `anxiety` のSkill ID、潜在要素を持つ対応NPC／Anomaly Entity一覧、対象内の `whisper` の持続・状態変化・対人使用可否。
- 他マップ候補解放実績の保存形式、途中切断後の候補状態、例外マップ、再受注・再発生条件。
