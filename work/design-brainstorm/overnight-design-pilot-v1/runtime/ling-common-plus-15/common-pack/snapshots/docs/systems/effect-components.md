# 共通Effectと保存境界

**Status: Designed（共通の分類と既定規則に合意済み。個別設定・実装は未確定）**

この文書は、スキル、アイテム、Anomaly Entity、Player Anomalyが引き起こす効果を共通の言葉で記述するための分類、保存境界、重ね掛け・解除の既定規則を定義する。すべてを同一の実体やServiceへ統合する仕様ではない。個別の能力・アイテム・アノマリーの挙動は、それぞれの資料で定める。

## 設計方針

永続的に蓄積した能力だけで優位性が決まる構造にはしない。解放済みの選択肢や持ち帰りやすさは成長要素として残しつつ、Run中のビルド、操作、観察、判断が結果を左右することを優先する。既存のスキルレベル1～3、ランク解放、Secure Slot強化を廃止する判断ではない。具体的な数値バランスは未決定。

ダメージ計算では、多数の変動係数や乱数を初期の共通仕様へ持ち込まない。小・中・大など既存の効果表現の数値化や固定値の扱いは、個別の戦闘設計で決める。既存の開錠成功率、アノマリー出現補正、BLOODMOONの自傷、PvPのHP下限など、明示済みの割合・確率ルールはこの方針で変更しない。

## Effectの種別

| 種別 | 扱う変化の例 | 境界 |
| --- | --- | --- |
| `Damage` | HPへのダメージ、遅延ダメージ | 命中、PvP下限、自傷などの最終判定は個別ルールに従う |
| `Heal` | HP回復、Heal入力への反応 | Mad Stomperの鎮静はHP回復そのものとは区別する |
| `StateChange` | Stun、構え、鎮静、追従先などの状態遷移 | Player Anomalyへの変化を汎用状態異常と同一視しない |
| `Move` | ダッシュ、Teleport、Knockback、位置変更 | 誰を移動させるか、経路上の判定は個別に定める |
| `InformationChange` | Detect・Recognition、可視性差、情報の信頼性 | Serverの共有事実とClientごとの提示・認識を分ける |
| `WorldChange` | 出現率・同時出現数、経路・Portal・Map状態などの世界変化 | 個人表示だけでRun共有状態を確定しない |
| `RuleOverride` | 入力結果の無効化、通常攻撃の置換、通常帰還の禁止など | 「その他」の無制限な受け皿にしない。適用対象と優先順位を個別に明記する |

一つの行為が複数のEffectを起こしてよい。種別は相互作用の入口や対象の種類ではなく、**結果として何が変わるか**を表す。例えばHealスキルへのMad Stomperの反応は、入力を受ける[Anomaly Interaction](anomaly-interaction.md)と、結果の`StateChange`を分けて記述する。`Player Anomaly`と`Anomaly Entity`は同じEffect種別を利用できても、状態本体とライフサイクルは別に保持する。

## 作用範囲と保存境界

「誰に作用するか」と「いつまで残るか」は別の項目とする。作用範囲には個人、Party、Run全体などがあり、保存境界は次の四つを基本とする。

| 保存境界 | 終了の基準 |
| --- | --- |
| 永続 | Runをまたいで保持する。取得・解除条件は個別に定義する |
| 同一Run中 | 当該Runの終了で破棄する。マップ遷移では原則保持する |
| 同一マップ中 | 当該マップから離れた時点で破棄する |
| 一時 | 指定された終了条件が成立した時点で解除する |

一時効果の終了条件には、固定秒数、対象との距離条件の逸脱、特定アイテムの干渉などを指定できる。複数指定された場合は、個別に別の規則を定めない限り**いずれかが成立すれば解除**する。マップ終了・Run終了による境界上の破棄は、一時効果にも適用する。固定秒数、距離、対象喪失などの評価主体とタイミングは実装時に定義する。

例として、出現率変更アイテムの効果は「Run全体に作用・同一Run中だけ保持」、Player Anomalyの状態は「対象プレイヤーに作用・同一Run中」と記述できる。ただしPlayer Anomalyの固有Runtime、死亡・帰還時の解除は[既存判断](../decisions/019-player-anomaly-runtime-pvp-and-return.md)を優先する。

## 重ね掛けの既定規則

- `Damage`や`Heal`などの即時効果は、発動イベントごとに解決する。持続効果の重ね掛けとは区別する。
- **同じEffect IDが同じ対象に再適用された場合、既定では効果量を足さず、1件として扱う。**固定秒数の一時効果は残り時間を更新する。距離などの条件式は再評価する。再適用時の正確な開始時刻・延長方法は個別に定義する。
- 異なるEffectは、変更先が競合しなければ共存できる。同じ値・行動・世界状態を変更する場合は、自動合算も「最後の適用が勝つ」方式も既定にしない。解決規則が未定義なら、その競合適用は保留し記録する。
- `加算`、`回数蓄積`、`強い方へ置換`、別の優先順位などは、個別Effectが明示する場合だけ使う。何を同一Effectと見なすか、出所が異なる場合の識別方法は実装仕様で決める。

博士Questによる同一対象の1.40倍補正がParty人数分重複しないことは[既存判断](../decisions/016-party-professor-quest-spawn-snapshot.md)に従う。一方、同一マップでアノマリーが発生するたびの0.90倍は、同じ一時効果の重ね掛けではなく、発生回数に応じたRun状態の更新である。アイテムによる出現コンポーネント変動の重ね方は引き続き未決定とする。

## 解除の既定規則

効果は自身に定義された終了条件と保存境界によって解除する。解除手段が明記されていない効果を、別のスキルが汎用的に消せるとは扱わない。

`cure`は「解除可能な状態異常」のみを対象とする。Exposure、Player Anomalyへの変化、Quest進行、出現率変更、永続解放を一括解除しない。何を解除可能な状態異常とするか、複数ある場合の対象と順序は個別仕様で定める。

## 記述時の最小項目

個別資料では必要に応じて、`Effect種別`、発動条件、対象、作用範囲、保存境界、終了条件、重ね掛けの例外、Serverが確定する状態、Clientの提示を記録する。これは共通の記述契約であり、直ちに万能なECSやEffect Serviceを実装する指示ではない。相互作用の入力文脈は[Anomaly Interaction](anomaly-interaction.md)、観察の証拠と認識段階は[観察・認識システム](observation-and-recognition.md)を参照する。

## 未決定事項

- 同じ値に異なるEffectが作用する場合のカテゴリ別解決規則。HP、移動速度、出現率、可視性、RuleOverrideの競合を含む。
- Effect ID、出所、対象、範囲を識別するデータ形式と、再適用の正確な処理。
- 距離条件やアイテム干渉を評価するタイミング、切断・対象消滅時の解除。
- 個別の固定値、Cooldown、上限、解除可能な状態異常の一覧。
- RuleOverrideと`/dev/null`のような結果傍受を、通常結果や他のEffectへどの順で適用するか。
