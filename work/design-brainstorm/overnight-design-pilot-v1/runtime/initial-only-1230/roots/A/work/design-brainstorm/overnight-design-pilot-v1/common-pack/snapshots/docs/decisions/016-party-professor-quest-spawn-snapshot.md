# 016: Party Runにおける博士Quest出現補正の固定

**Status: Accepted（採用）**
**Date: 2026-10-02**

## 背景

博士Questは、対応アノマリーの個別出現確率を1.40倍へ上げる。Partyの各プレイヤーが別々の博士Questを持つ場合、どの対象を補正するか、同じQuestの重複をどう扱うか、途中脱落で補正を再計算するかが未決定だった。

Run中にParty構成を基準に出現率を下げると、仲間が脱落した時点でマップの危険度まで下がり、開始時の協力構成が持つリスクが消える。

## 決定内容

### Run開始時のサーバー状態

サーバーはRun開始時に、開始時Partyの博士Questから対応アノマリーIDの集合を作り、Run初期状態として保持する。

- 各プレイヤーは博士Questを1件まで受注できる。
- 異なるQuest対象は、それぞれ個別出現確率を基礎値の1.40倍へ上げる。
- 同じ対象を複数人が受注しても、1.40倍の補正は一度だけ適用する。
- この対象集合と補正は、クライアントではなくサーバーが保持・判定する。

### 脱落後の扱い

Run開始後にプレイヤーが死亡、離脱、切断しても、初期状態の対象集合を再計算しない。補正対象の個別出現確率は下がらない。

複数人が異なる博士Questを受注して開始したRunは、各対象が補正された状態で始まる。途中でソロになってもその状態を維持するため、ソロ開始時よりアノマリー遭遇率が高くなり得る。これは、マルチで開始したRunが持つ高難易度の一部である。

### 既存の出現減衰との関係

個別対象への1.40倍補正は、アノマリー1体の発生ごとに全候補へ掛かる0.90倍の減衰と併用する。発生済み数を`n`としたとき、開始時に固定された博士Quest対象は`基礎個別確率 × 1.40 × 0.90^n`となる。

## 影響

- `RunService`またはAnomaly出現を管理するサーバー側サービスは、開始時の対象ID集合を保持する必要がある。
- Partyメンバーの生死・接続状態を毎回出現補正へ反映しない。
- 同時出現数コンポーネントと、候補のないマップでの扱いは[017: Run単位のアノマリー出現コンポーネント](017-run-anomaly-spawn-components.md)で定める。

## 未決事項

- 初期対象集合をプレイヤーへどこまで表示するか。
- 再接続者がRunの初期状態と結果をどう受け取るか。
