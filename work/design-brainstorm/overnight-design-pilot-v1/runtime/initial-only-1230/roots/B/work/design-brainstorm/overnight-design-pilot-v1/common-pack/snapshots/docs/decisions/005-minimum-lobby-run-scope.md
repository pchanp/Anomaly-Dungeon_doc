# 005: 都市ロビーから開始する最小Runの範囲

**Status: Draft（草案）**
**Date: 2026-09-29**

## 背景

Abandoned TSUTAYA と 8月31日は個別マップのプロトタイプとして生成できる。一方、現在の `RunService` は単一の生成世界を扱い、都市ロビー、ダンジョン入口ロビー、正式なパーティ形成、リザルト画面、並列Runを持たない。

複数マップのネットワークと状態依存ポータルは将来の設計として維持しつつ、まずはダンジョン入口ロビーでパーティを組み、ランダムに決まる一つの探索先を完結して戻る最小Runを成立させる。

## 現時点の判断

### Runの境界

- 最小版のRunは **都市ロビー -> ダンジョン入口ロビー -> ランダムに選ばれた1マップ -> リザルト画面 -> 都市ロビー** とする。
- Run中の `TSUTAYA <-> AUGUST_31` 遷移は実装しない。Transition Portal と Party State はこの範囲外とする。
- 対象マップは `TSUTAYA` と `AUGUST_31` の2種とする。`CLOSED_STACKS` はデバッグ／既存プロトタイプ用途として残し、最小版の選択肢には含めない。

### 選択と共有範囲

- 都市ロビーからダンジョン入口ロビーへ移動し、入口ロビー内のパーティ用フィールドに先着したプレイヤーでパーティを形成する。マップを選ぶ投票、Ready、リーダー権限は導入しない。
- パーティ人数の上限は5人とする。最初のプレイヤーがパーティ用フィールドへ入った時点で30秒の受付を開始し、満了時点の参加者で出発する。
- デバッグ用途として、受付を即時終了して出発処理へ進める強制締切スイッチをダンジョン入口ロビーに置く。このスイッチは通常の出発条件を置き換えるものではない。
- 出発時にサーバーが `TSUTAYA` と `AUGUST_31` から等確率の完全ランダムで1マップを選ぶ。クエストの内容・達成状況はこの抽選に関与しない。
- 将来は、各マップのコンポーネント、プレイヤーの所持品、スキル構成などを入力として候補マップの重みを変動させ得る。ただし最小版では抽選に重み・条件・補正を持ち込まない。
- 最小版ではサーバーごとに一つのアクティブなパーティRunと一つの生成世界だけを持つ。パーティ別インスタンスや、探索中の別パーティへの途中参加は導入しない。
- 出発時にパーティ用フィールド外にいるプレイヤーは、ダンジョン入口ロビーに残る。進行中Runへの途中参加はできない。
- マルチプレイヤー向けのサーバー割当、複数パーティの同時運用、再接続、サーバー間移動は仮置きであり、この最小版の仕様確定には含めない。

### Questと帰還

- 各Runの基本Questは、抽選されたマップ定義が示す1つの目標とする。最小版では、マップ内の出口制御端末を操作して出口を有効化する型を共通に用いる。
- Questはマップ抽選へ影響しない。マップ遷移先を操作するための条件にも、プレイヤーを特定マップへ誘導する条件にも使わない。
- Run終了時は必ずリザルト画面を経由する。リザルト画面には、獲得物と保有Questごとの達成状況を表示してから都市ロビーへ戻る。
- Quest完了後に通常帰還した場合のみ、固定の基本報酬を支払う。未完了での任意帰還、死亡、切断は失敗扱いで基本報酬を支払わない。
- リザルト画面の基本項目は、**獲得物**、**喪失物**、**保有Questごとの達成状況**とする。
- 成功して帰還した場合、Run中に確保した持ち帰り対象は獲得物として扱う。失敗した場合、Secure Slot内の物だけを獲得物として保持し、それ以外の持ち帰り対象は喪失物として扱う。
- プレイヤーの総インベントリは20枠とし、そのうち初期状態の4枠をSecure Slotとする。通常プレイヤーはスキル強化によってSecure Slotを拡張できる。
- Discovery、収集品、換金、Inventory、Secure Slot、マップ固有の追加報酬は未実装である。ただしリザルト画面とRun終了処理は、この成功・失敗時の資産処理を表せる境界として設計する。

### 8月31日固有の扱い

- 夕方のReturn Portalは、Quest未達でも都市ロビーへ戻るための任意帰還手段として扱う。未達なら基本報酬はない。
- 8/32は `AUGUST_31` 内の状態変化であり、別マップへの遷移ではない。
- 8/32のRun Lifetime満了は死亡扱いの失敗とする。リザルト画面へ遷移し、基本Questの成功・基本報酬を与えない。生存報酬、Rare Loot、強制Anomalyは正式なInventory・Anomaly Systemの導入後に別途決める。
- 8月31日の時計は、当該共有世界に探索者がいる間だけ進行する。都市ロビーへ全員が戻った後に同じ世界を再利用するか、次の出発時に再構成して初期状態へ戻すかは、最小版では **再構成して初期状態へ戻す** とする。

### 状態の初期化

- 都市ロビーからダンジョン入口ロビーへ入る時点で、HP、Anomaly Exposure、Player Anomaly、Run内Quest状態を新しいRun用に初期化する。
- 成功・任意帰還・死亡・8/32での失敗を問わず、Run終了時はリザルト画面へ遷移する。リザルトを閉じて都市ロビーへ戻った時点でRunを完全に終了する。将来の永続進行へ反映するのは、確定したQuest報酬だけとする。

## 理由

- 単一 `world` を扱う既存構成のまま、パーティ形成、ランダムな目的地決定、入場、リザルト、帰還というコアループを縦に検証できる。
- 複数マップ間の遷移を先に入れると、Party State、残留プレイヤー、所持品、Quest継続、死亡時の合流先を同時に決める必要がある。
- 8/32の危険な状態変化は維持しつつ、未実装の報酬・Inventory・Anomaly生成を成功条件に偽装しない。

## 実装前になお必要な詳細

- 都市ロビーとダンジョン入口ロビーの実体（2Dワールドマップ、施設内3D、または最小の出発地点）と、パーティ用フィールドのInteraction。
- ランダム抽選のseed・再抽選可否、将来のマップコンポーネント・所持品・スキル構成による重み付けの計算と可視化、パーティ受付を開始するフィールド境界、強制締切スイッチの権限・表示、再構成時のプレイヤー位置、都市ロビーのSpawn位置。
- 端末以外のQuest条件、報酬値、切断・サーバー再起動時の扱い。
- 保有Questを複数持つためのデータモデル、持ち帰り対象の定義、Secure Slotの入出庫タイミング・拡張上限・強化コスト、リザルト画面での獲得物・喪失物・Quest結果の表示詳細。
