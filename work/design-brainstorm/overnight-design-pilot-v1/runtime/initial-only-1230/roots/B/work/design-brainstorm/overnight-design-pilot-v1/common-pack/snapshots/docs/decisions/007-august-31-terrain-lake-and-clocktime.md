# 007: 8月31日マップの地形・湖・時計の再設計

**Status: Prototype: Implemented（実装済みプロトタイプ）**
**Date: 2026-09-30**
**関連実装:** `ServerScriptService/AnomalyDungeonServer/Maps/August/AugustTerrain`、`ServerScriptService/AnomalyDungeonServer/Maps/August/AugustGenerator`、`ServerScriptService/AnomalyDungeonServer/Maps/August/August31Service`、`ReplicatedStorage/AnomalyDungeon/Shared/Config/AugustConfig`

## 背景

[003](003-august-31-time-and-phase-design.md)の実装後、8月31日マップを実プレイで確認したところ、次の状態になっていた。

- `Lighting.ClockTime`が`0`のままで、8月31日のマップが真夜中に描画される。
- 各ゾーンの床が `y=1000` から `y=1044` の平坦な台地として生成され、ゾーンとゾーンの境に階段状の崖（壁）が露出する。
- 湖、遠景の山、広い植生が存在せず、参照元の田園風景にはほど遠い。

原因は3つあった。

1. ゾーンの床が「中心の高さに固定した2スタッドの板」で、ゾーン内でも地表が3〜6スタッド起伏するため、床板が地中に埋もれていた。
2. ゾーンの平坦化のブレンド係数が逆向きで、境界の直外で自然地形へ飛びしていた。高低差が連続せず、壁として見えていた。
3. 湖のへこみが自然地形との差分として定義されていたため、湖の領域が尾根と重なると湖底が尾根の上に乗ったままになり、湖底が水面より上になって水体が現れなかった。正方形の水板は、地形の低い方位で湖の外へにじみ出していた。

また003は「`ClockTime`は変更しない」という判断を記録していた。実装が確定するまでこの判断を維持していた。

## 決定内容

### 時計

- `ClockTime`をフェーズごとに明示的に持ち、`DAY=13.5`、`EVENING=18.4`、`NIGHT=23.2`、`AUG_32=23.6`を設定する。
- 003の「`ClockTime`は変更しない」という判断は本記録で置き換える。
- `Lighting`の所有権とUnbind時の完全復元は003のまま変更しない。

### 地形

- 地形計算を `AugustTerrain` として独立モジュールへ切り出す。責務は「自然地形」「湖のへこみ」「尾根」「ゾーンの平坦化」「地表メッシュ生成」の5点。
- 谷底は正弦波の重ね合わせで緩い起伏を持ち、尾根は複数の滑らかな山を重なりで作り出す。
- 描画分割とゲームロジックで同じ高さ関数が使われるようにする。

### ゾーンの平坦化

- 建造物と床板は水平でなければ歩けないため、**地形側をゾーンに合わせる**。
- ゾーンの内部はその高さで固定する。外部では、影響するゾーンをすべて重み付けで重ねてから自然地形へ戻す。
- 最も近いゾーン1つだけを選ぶ実装は、2ゾーンの境で高さが飛び不連続な壁になるため採用しない。

### 湖

- 湖のへこみは自然地形との差分ではなく、**地形そのものの絶対高**として返す。
- 水面は円柱を下向きに寝かせた円盤とし、縁は地形で覆われる半径を取る。
- 湖の位置は、地形を数値で走査し「尾根の重なりが無く、谷底の振幅が小さく、ゾーンと干渉しない」位置を選定した。選定とセットで、湖に被っていた南側の尾根を後退させ、`APARTMENT` を湖の外へ移している。

### Trail

- 路面を地形に沿って分割し、各区間の両端を地形高に合わせる。分割幅は12スタッド程度まで細かくする。
- 1枚の板で2点結ぶ方式は、湾曲した谷底に対して弦が地面から浮くため採用しない。

## 判断理由

- 003が`ClockTime`を禁止したのは「時刻の概念はフェーズで持つ」という理由だった。実際にはフェーズは名前と進行の器に留まり、描画の光源は`ClockTime`から独立していない。8月31日を昼として描くには、光源側の変更が避けられない。
- 壁と高低差の二つは、どちらも描画の問題ではなく高さ関数の問題である。地形計算を1箇所へ集約し、原因をそこでのみ直した。
- 湖を絶対高で掘ると、谷底がどこにあろうが「水面から水深だけ下がる」という関係が保たれる。尾根の再配置と一体で判断した。差分方式では湖を成立させられる位置が尾根の配置に強く依存し、尾根を動かせば湖そのものが消える。
- Trailの分割幅を半分にすると段差も半分になるため、分割を細かくする方針で足りると判断した。

## 影響

- `ValleyGround` のインスタンス数が増加する。分割を14スタッドにした結果、1マップあたり約13,000 BasePart になる。`StreamingEnabled` による流入制御に依存する。
- 尾根の急斜面にはタイル1枚ぶんの段差が残る。尾根の半径と高さを変えれば消せるが、谷を囲む形状が弱まるため今回は据え置いた。
- `result.GroundTiles` に生成したタイルを保持するため、8/32のParts走査とは別系統になる。
- `MapDrawConfig` は変更していない。`TSUTAYA` と `AUGUST_31` の等確率抽選はそのまま。

## 未決事項

- 尾根の段差。分割をさらに細かくする、尾根を緩やかにする、Terrain機能を使う、のどれが妥当かは未検討。
- 建物・商店街・学校・追加植生は旧生成物を流用している。参照イメージに合わせた再構築は未着手。
- 湖と `APARTMENT` を結ぶTrailがネットワークに含まれていない。
- 隣接ゾーンの高さの最大差が15スタッドあり、ゾーン間に傾斜の土手が生まれる。ゾーン配置の平坦化は未検討。
