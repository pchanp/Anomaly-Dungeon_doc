# 候補HTMLとJSONの形式 v0.2

Status: Draft。2026-10-05のユーザー指示を反映。

## HTML：案と仕組みだけを短く読む

1. タイトル、候補ID、対象マップ、Idea/Draft。
2. 「何の案か」1文（60字程度）。
3. 「仕組み」2〜3箇条。発動、変化、終了を具体的に。
4. 「プレイヤーの選択・代償」1〜2文。
5. 意味のある固有インラインSVG図1つ。図注1文。
6. 同IDのJSONとindexへのリンク。接続タグ、requires_codeは必要なら1行。

目安は図内文字を除く説明本文250〜450字。長い根拠説明、仕様との整合性の弁明、Server/Clientや保存境界の網羅、未確定事項の列挙、採用時の注意はHTMLへ書かない。図を見た人が何の案でどう動くか分かることを優先。見出しの固定IDはhypothesisとdiagramだけ。CSS/画像/フォント等の外部依存なし。

JSONには既存schema_version 0.1の必須項目、根拠、Effect、矛盾、保存境界、担当別項目を保持するが、各項目も短い文章で書く。JSONの内容をHTMLへ全転記しない。根拠のない世界の真相・他担当案を創作しない。無関係な整合性の説明で水増ししない。

manifestは既存形式: run_id、role、candidates配列（candidate_id/json_file/html_file）。完成後に記載。indexから全15件へリンク。予約001〜015とマップ配分は変更しない。
