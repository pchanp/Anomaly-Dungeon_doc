# 追加回 v0.3 — 全マップ共通・ソロPvE重視

Status: Draft。ユーザーの追加依頼。既存001〜015へ追記する016〜030を各担当15件作成。既存候補の置換は禁止。
全マップ共通は8/31・廃TSUTAYA・SEKIGAHARA・研究所で使用文脈を持てること。特定マップの器材・NPC・Quest・Party人数を発動必須条件にしない。全マップで必ず配置されるとは確定しない。

## 最優先

一人で遊んだときの移動、戦闘回避、間合い、探索、環境への介入、危険と報酬の選択を考える。まず遊びの動詞と起こる変化を書き、その後にEffect契約を整理する。コンポーネントを組み合わせることや他担当への接続それ自体を面白さにしない。
Partyの同意・同時入力・受け渡しを必要とする案を作らない。協力は任意の拡張だけ。無意味なHUD記録・提示だけの案、単なる数値上昇、鍵・札の言い換え、操作封じだけが代償の案を量産しない。
15案は異なる遊びの核にする。少なくとも操作で避ける、攻める、探す、引き返す、環境を利用するという判断を複数含める。敵AIやマップの未実装部分は仮説と記すが、効果の中身を空欄にしない。

HTMLはv0.2と同じ簡潔形式。何の案か1文、仕組み2〜3項、選択と代償、意味のある固有SVG。長い整合性説明は不要。詳細JSONはschema0.1を維持。componentsは必要最低限、新規が要ればproposed/requires_codeで記録し、既存に無理に寄せない。refsは空配列でよい。接続タグだけでもよい。
世界観不変条件・Effect分類・保存境界・既定重ね掛けは維持。研究所構造やQuestの結末、Entityの正体を決めない。通常SkillとPlayer Anomaly専用能力を分ける。
各担当001〜015とhandoffを先に読む。016〜030だけ新規作成。index/manifest/progress/events/handoffは30件へ追記更新し、旧候補を削除・書き換えない。
3件保存ごとに進捗更新。15追加で停止し確認待ち。時間制限なし。実装・採用・Git・Studio・公開サイト更新は行わない。管理側が検証する。ブラウザ未実施ならunavailable。
